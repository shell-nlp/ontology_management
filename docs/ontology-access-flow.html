本体访问流程：两条入口，一层 lib

REST（界面点按钮）与智能问答 / MCP（模型与外部 agent）不互相调用，各自进入 HTTP 层， 但都落到同一层 lib，读同一批存储。差别只有三处：读写 vs 只读、全部版本 vs 已发布版本、权限点 vs 工具开关。

写路径（只有 REST） 只读路径（问答 / MCP） 共用层内部调用
为什么共用
工具实现只 import @/lib/…，不 fetch 自家 /api/ontology —— 两条入口在进程内落到同一层服务； 所以换了存储（定义从磁盘搬到 PG）时，REST 与工具都零改动。
定义存哪
定义与实例快照都在 ontology_versions 的两个 jsonb 列；概念索引在 ontology_concepts； 图库里只有发布后的投影，读不回完整定义。
一条写入口
改定义只有 PATCH /api/ontology/[versionId]，改实例只有 /api/instances/*（内部先建草稿）。 工具侧没有任何写路径。
