# 功能实现记录

这份文件是给人看的**功能账本**：现在这个平台能用什么、入口在哪、有什么限制、怎么验证。

- 写法：按时间**倒序**，最新的一批在最上面；每条只写"**已经实现并验证过**"的东西。
- 分工：提交历史看 `git log`；工程约定、踩过的坑、别往回改的设计看 `AGENTS.md`；这里只讲"有什么功能、怎么用"。
- 维护约定（2026-10-08 用户要求：「实现的功能都要记录下来，因为都是 AI 写的」）：
  **每完成一批功能就回来追加一条**（日期 + 做了什么 + 入口 + 限制 + 怎么验证），不要只留在对话里。

## 2026-10-08 · 智能问答工具链增强（本轮）

起因：跑了两轮真实问答（互联网专线带宽统计、短彩信欠费金额），模型用了 13~16 次工具调用，指出 8 条问题；
逐条核对后挑出真问题做了这一批。

### 1. `search_schema` v2（语义检索）

- **能用了**：默认返回 20 条（上限 50）；入参 `kinds`（只看某几类概念）、`object_type`（只看挂在某个对象类型下的概念）、`include_values`（是否用列画像做取值检索）、`limit`（`max_concepts` 的别名）。
- **每条命中带"落点"**：`matched`（`name` / `value` / `description` / `fallback`，说明凭什么命中）+ `bound_table` / `source_column` / `object_type` / `description`。查一次就能直接拿去写 SQL，不用再回查 `get_object_type`。
- **检索面**：对象类型名、说明、分组、绑定的表、属性名、**属性说明**、接口名与实现方、指标名与口径。
- **打分**：名字完全一致 100 / 包含 70（这两档不再叠加）→ 列取值命中 45 → 描述命中 30 → 长问题退回按词命中（最多 3 个词）。不传 `kinds` 时对象类型 / 指标 / 关系类型**保底占一半名额**，属性不会刷屏。
- **明确挡住"枚举库表"**：返回里固定写「表只能通过对象类型到达」，`list_tables` / `search_columns` 按用户口径**没有实现**。
- 位置：`src/lib/reasoning/tools.ts`（`schemaConcepts` / `rankSchemaConcepts` / `applyTypeQuota`）、提示词 `src/lib/reasoning/prompt.ts`。
- 验证：`tests/lib/reasoning/tools.test.ts` 的「search_schema v2」用例（含 6 条旧断言，保证名字命中没回归）+ 对真实本体的 MCP 调用。
- 限制：没有同义词 / 别名层（"政企"这类说法还是靠名字与说明命中）；取值命中依赖该表的列画像已缓存（见第 3 条）。

### 2. 指标（Metric）——业务口径层

- **能用了**：一条指标说清「这个数怎么算」：作用对象类型、聚合方式（SUM / COUNT / COUNT_DISTINCT / AVG / MIN / MAX）、被聚合属性、固定口径过滤、可用维度、时间维度、单位、标签。它只描述口径，**不是查询结果**。
- **入口**：本体建模新增「指标」标签（排在「接口」之后）；模型侧有 `list_metrics` 工具，`get_object_type` 也会带上这个类型上的指标，系统提示词的「本体概念清单」里有一行「指标：…」。
- **发布前校验**：重名 / 作用类型不存在 / 聚合属性、过滤、维度、时间维度指向不存在的属性 → **挡发布**；没选作用类型、`SUM/AVG/MIN/MAX` 用在非文本属性上 → 只提醒。
- **出包**：本体包 `definition.metrics[]`；结构化清单里写 `metrics[].scope`（对象类型名）与属性名，编译器负责翻 id 并当场校验；示例包与文档同步更新。
- 位置：`src/lib/ontology.ts`、`src/lib/metrics.ts`、`src/components/metric-manager.tsx`、`src/lib/bkn-import.ts`（bkn 导入不再丢指标）、`skills/ontology-bundle/`（格式与示例）。
- 验证：`tests/lib/skills.test.ts`（示例包带指标仍"零违规"）、`tests/lib/reasoning/tools.test.ts` 的指标用例、`tsc`。

### 3. 列画像（column profile）——表的取值长什么样

- **能用了**：`get_table_ddl` 现在连**列画像**一起返回：每列采样 1000 行后的取值种数、空值比例，**低基数列直接给取值清单**（例如 `USR_STATUS` = 未停机 / 报暂停 / 申请销号 / 欠费停…）。
- **成本红线**（用户口径：Oracle 大表 `COUNT(DISTINCT)` 很贵）：只对**被对象类型绑定的表**做；只**采样**不做精确统计；取值种数 >50 的列按高基数列处理（不存取值）；结果写 `column_profiles` 表（迁移 0003），**按天复用**，只有 `refresh: true` 才重采。
- **一张表被谁用了**：同一返回里给 `bound_object_types`（哪些对象类型绑定它、各映射了哪几列、是主来源还是补充来源）；没有任何对象类型绑定就明说"表只能通过对象类型到达，先确认表名"。
- 位置：`src/lib/column-profile.ts`、迁移 `src/lib/db/migrations/0003-column-profiles.ts`、`tools.ts` 的 `get_table_ddl`。
- 验证：`tests/lib/column-profile.test.ts`（纯逻辑）+ `tests/lib/column-profile.contract.test.ts`（真 Oracle 采样 → 落缓存 → 第二次命中 → 值检索命中；默认跳过，文件头写了怎么跑）。
- 限制：没有分区键 / 最新分区值 / 表行数（当时只做了"采样画像"这一层）。

### 4. 关系类型的数量关系（cardinality）

- **能用了**：关系类型可以标 一对一 / 一对多 / 多对一 / 多对多（空 = 未标注）。说的是**起点端 → 终点端**的数量关系，回答的是"走一次会放大几倍"——一个客户 141 条专线，按客户聚合就会重复计数。
- **不是**正向 / 反向名字：`AGENTS.md` 里"关系类型双向、不配正反向名字"的口径不变，两个方向照样都能走。
- **入口**：编辑关系类型的弹窗里有下拉（带每个选项的一句话解释）；工具侧 `get_object_type` 的每条一跳关系带 `cardinality`（声明原样）+ `cardinality_label` + **`cardinality_from_here`**（从当前这个对象类型看过去的说法，入边会翻过来说），`traverse_object_types` 的边也带 `cardinality`，`search_schema` 的关系类型 detail 里写「基数 一对多」。
- 位置：`src/lib/relationship-cardinality.ts`、`src/lib/ontology.ts`、`src/components/type-edit-dialog.tsx`、`src/lib/reasoning/tools.ts`。
- 验证：`tests/lib/relationship-cardinality.test.ts` + `tools.test.ts` 里"工具里的说法"一组用例。
- 限制：bkn 导入的旧数据没有这个字段（导入后是"未标注"，需要人工补）；它只是声明，不参与任何自动校验或推理。

### 5. `run_sql` / `get_table_ddl` 的耗时

- **能用了**：两个工具的返回里都带 `elapsed_ms`（这次实际花了多久）。`run_sql` 的工具说明里也写清了"一次调用可以带多个 CTE，把探码值 + 汇总 + 校验合并成一条语句更省"。
- 验证：真机 MCP 调用（`get_table_ddl` 读远端 Oracle 数据字典 + 采样约 2.6s）。
- 限制：没有 `scanned_rows`（Oracle 上要靠 `EXPLAIN`，不稳定）与结果缓存（属于另一个工程）。

### 6. 修掉一个真 bug：工具结果被截断后回放给模型

- **问题**：`steps[].result` 以前截在 8000 字符，而它同时是**下一轮对话回放给模型的 tool-result**。一个 66 个属性的对象类型定义有 1.7 万字符，于是模型在追问里会说"某个字段没返回"——它看到的是半截 JSON。
- **现在**：存到 60k，真超了也写明"原长多少、截到哪里"（`truncateForHistory`）。
- 位置：`src/lib/reasoning/agent.ts`；验证：`tests/lib/reasoning/agent.test.ts`。

## 更早的功能（按主题汇总）

### 本体建模

- **可视化建模画布**：加对象类型、从节点拉关系类型、拖动节点（三种布局：默认 / 圆形 / 按逻辑分组），概念分组的框跟着节点实时收缩扩大；"自动整理"清掉手工位置。连线都能点开就地编辑（含接口虚线、接口承接的青色实线）。
- **概念分组（业务域）**：把对象类型归堆，"按逻辑分组"布局按组画框；分组进检索面与工具（`list_concept_groups`）；bkn 导入自动带分组。
- **接口**：Palantir 风格的抽象契约（属性、关系约束、继承、实现；一个对象类型可实现多个接口）。无数据源的对象类型可以「提取为接口」，原关系转成接口约束；**实现接口 = 继承接口的关系类型**，画布、工具、右栏三处都对齐。没有父子继承这一套（2026-09-16 已删）。
- **关系类型**：键映射（连接属性 → 对象类型属性，写多行就是复合键）、关系的数据来源（连接表式 / 外键式，D2）、数量关系（本轮）。
- **动作与规则**：动作定义（作用对象类型、入参、写哪些属性）+ 规则（BLOCK / WARN / HIDE），动作引擎带干跑与决策记录。
- **建模体检**：空壳、孤悬、主键列接不上、命名打架等一批规则的离线体检（只建议、不挡发布）。
- **版本与草稿**：创建草稿 → 校验 → 发布（多实例安全的原子替换）；页头显示「当前版本 vN」，版本记录与历史激活在页头。

### 本体实例

- **对象服务**：索引优先、没有就按主键回源；对象页、图谱页、实例工具走的是同一份身份。
- **对象索引**：PostgreSQL 索引（tsvector + pgvector 列），抽象成可替换后端 + 契约测试；未来换 ES/OpenSearch 只换实现。
- **实例工具**：`query_object_instance`、`query_instance_subgraph`（按类型取对象、取子图）。

### 智能问答（本体 Agent）

- 用 **Vercel AI SDK v7 的 ToolLoopAgent** 跑工具循环（框架负责循环、消息与裁剪），平台自己只做编排、提示词与界面事件。
- 流式输出、思考过程开关、**中途停止**（停止也算一份可回看的运行记录）、思考与工具轨迹分开显示、工具入参与返回都能展开看。
- **多轮上下文**：最近 5 轮原样回放 + 更早的压成摘要（压缩交给框架），界面上能看到"上下文 N 轮 · 已压缩 M 轮"。
- **图片输入**：问句可以带图（浏览器侧先缩图，历史里只记张数不重发像素）。
- **对话历史**：会话列表、回看以前的问答、删除会话。
- **工具开关**：平台级启停单个工具，关掉的工具模型看不到（MCP 调试页里灰着显示）。
- **自定义系统提示词**：问答配置里可改，界面显示默认提示词。
- 工具集：`search_schema`、`get_object_type`、`list_concept_groups`、`list_interfaces`、`traverse_object_types`（默认 3 跳 / 最多 5 跳，可限定类型与方向）、`list_actions`、`list_metrics`、`get_table_ddl`、`run_sql`（只读 + 行数上限 + 截断提示）、两个实例工具。

### 数据资源

- PostgreSQL / MySQL / Oracle 三种关系库的连接管理（凭据加密保存）、表 / 视图浏览、结构缓存（查一次存平台库，手动刷新才回源）、连接池与并发闸门、只读 SQL 闸门（词法 + 只读事务）。
- 对象类型绑定数据来源：主来源决定身份与标题，补充来源按主键补齐属性；一个对象类型可以挂多份来源。

### 平台与交付

- 平台库走 **TypeORM + 迁移**（业务代码不写 SQL），启动自动建表、自动创建首个管理员。
- **图存储抽象**：内置后端（平台自带，PG 持久化快照）与 **Apache Jena / Fuseki**（可选外部）共存，Neo4j 已整体移除。
- 审计日志（发布、动作决策、数据资源与工具开关变更都落库）。
- **OpenAPI 文档**：`/docs`（Swagger UI，构建时自动生成）。
- **Docker Compose 部署**：只部署本体平台 + PostgreSQL；Fuseki 不是必需项（要用就作为外部图引擎接进来）。
- **本体包**：导出 / 导入 `.ontology.json`（`format: ontology.bundle`），支持"结构化清单 → 脚本编译"（`build-bundle.mjs`，Windows/Linux/macOS 通用）。
- **bkn 知识网络导入**：对象类型、关系类型、概念分组、指标（本轮补上）自动转换。
- **本体技能**：三套建模技能（需求澄清 / 本体设计 / 出包交付），可整体下载 zip，也**直接发布为免令牌 MCP**（`/api/skills/mcp`）。
- **MCP 服务端**：`/api/mcp` 把本体查询工具暴露给外部 agent（会话或 Bearer token）。
