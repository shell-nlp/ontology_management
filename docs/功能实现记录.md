这个平台现在**有什么功能**、从哪进、有什么限制。只写已经实现并验证过的东西。

- **这不是修复日志**（2026-10-09 用户口径：「不是所有的修复记录都加进去，而是记录平台有什么功能」）：
  修 bug 不单独占一条，只有**用户看得到的新能力**才写进来；已有的能力变了口径，就改那一条，不另起一条。
- 按**功能分区**组织（分区跟左侧导航对齐），不按日期堆叠。
- 分工：提交历史看 `git log`；工程约定与"别往回改的设计"看 `AGENTS.md`；这里只讲"有什么、怎么用、有什么限制"。

## 本体模型（建模）

左侧「本体模型」分组 → **本体建模**。这一页是一排标签：可视化建模 · 概念分组 · 对象类型 · 关系类型 · 接口 · 指标。
（「本体技能」在下面单独一节。）

### 可视化建模

- 画布上直接搭模型：加对象类型、从节点拉出关系类型、拖动节点摆位，三种布局（默认 / 圆形 / 按逻辑分组），
  "自动整理"清掉手工位置。概念分组的框跟着节点实时收缩扩大。
- **每条连线都能点开就地编辑**，不跳页：普通关系类型、接口的紫色虚线（实现接口）、接口承接的青色实线，
  三类线各自能翻回"能编辑的那个东西"。
- 选中实现方对象类型时，它**从接口继承来的关系类型**会临时挂到它身上显示 —— 不选任何东西时仍只属于接口。

### 概念分组（业务域）

- 把对象类型归堆，分组颜色就是"按逻辑分组"布局画的那个框；分组只影响怎么摆、怎么画，不进图库、不改定义。
- 分组是**可选的、从既有分组里挑**的（不是随手填）：本体建模里有专门的分组配置页。
- 分组进检索面与工具（`list_concept_groups`），bkn 导入会带上分组。

### 对象类型

- 定义属性（名称 / 类型 / 说明）、主键、展示属性、所属概念分组、实现的接口、数据来源绑定。
- **没有父子继承**（已删）—— 平台里的抽象机制只有接口一种。
- 无数据源的对象类型可以「提取为接口」，原关系转成接口约束。

### 关系类型

- **是双向的**：一条定义、两个端点，建好之后两个方向都能走，不配置也不需要正反名字。
- 两端的键映射：连接属性 → 对象类型属性，写多行就是复合键。
- 关系的数据来源（连接表式 / 外键式），数量关系（1:1 / 1:N / N:1 / N:M）。

### 接口

- Palantir 风格的抽象契约：属性、关系约束、接口继承、实现关系；一个对象类型可以实现多个接口。
- **实现接口 = 继承接口的关系类型**：画布、工具、右栏三处都按这个口径算。
- 接口在本体建模里就地编辑（和「编辑对象类型」同一个壳），不用跳到「接口」标签。

### 指标（业务口径层）

- 一条指标说清「这个数怎么算」：作用对象类型、聚合方式（SUM / COUNT / COUNT_DISTINCT / AVG / MIN / MAX）、
  被聚合属性、固定口径过滤、可用维度、时间维度、单位、标签。**它只描述口径，不是查询结果**。
- 入口：本体建模「指标」标签；模型侧有 `list_metrics`，`get_object_type` 会带上该类型上的指标，
  系统提示词的概念清单里也有一行。
- 发布前校验：重名 / 作用类型不存在 / 聚合属性、过滤、维度、时间维度指向不存在的属性 → 挡发布；
  没选作用类型、SUM/AVG/MIN/MAX 用在非数字属性上 → 只提醒。

### 建模体检 · 校验 · 版本

- **建模体检**：空壳、孤悬、主键列接不上、命名打架等一批规则的离线体检 —— 只给建议，不挡发布。
- **发布校验**：端点契约、必填属性、指标与接口的一致性等问题在这里挡住。
- **草稿与版本**：创建草稿 → 校验 → 发布（多实例安全的原子替换）；页头常显「当前版本 vN」，
  草稿版本并列显示，版本记录与历史激活也在页头。
- 本体列表卡片支持编辑本体档案（名称 / 说明 / 标签 / 配色）。

## 动力模型（动作 · 规则）

左侧「动力模型」分组 → 动作 · 规则。

- **动作定义**：作用对象类型、入参、写哪些属性。
- **规则**：BLOCK / WARN / HIDE 三种拦截与提示。
- **动作引擎**带干跑与决策记录，每次决策落审计。

## 本体实例

左侧「本体实例」分组：实例图谱 · 对象 · 关系。

- **对象页**：按对象类型列出对象，可选数据来源口径 —— 已物化的对象（本体里有的）或业务库实时取数
  （表里有多少就能看多少）；能看属性、主键、一跳关系（关系实例读自业务库），可以改属性、跑动作、
  把业务库里的对象「取进草稿」再编辑。
- **关系页 · 实例图谱**：按类型看关系与子图。
- **对象服务**：索引优先、没有就按主键回源；对象页、图谱页、智能问答的实例工具走的是同一份身份。
- **对象索引**：PostgreSQL（tsvector + pgvector 列），抽象成可替换后端并带契约测试 ——
  以后换 ES / OpenSearch 只换实现，不动上层。

## 智能问答（本体 Agent）

左侧「能力验证 → 智能问答」。

- 用 **Vercel AI SDK v7 的 ToolLoopAgent** 跑工具循环：框架负责循环、消息与裁剪，平台只做编排、提示词与界面事件。
- **后台运行**：一轮问答由**服务端**跑，不挂在某条浏览器连接上。切到别的页面、按「新对话」换一段空对话、
  甚至刷新页面，那一轮都继续跑；对话历史里直接能看到哪一轮正在跑（那一条写着「运行中」），跑完自动出现在历史里。
- **流式输出**、思考过程开关、**中途停止**（只有点「停止」才真的停；切走只是不看了）、思考与工具轨迹分开显示、
  工具入参与返回都能展开看。
- **多轮上下文**：最近若干轮原样回放，更早的压成摘要（压缩交给框架），界面上能看到「上下文 N 轮 · 已压缩 M 轮」。
- **图片输入**：问句可以带图（浏览器侧先缩图，历史里只记张数、不重发像素）。
- **对话历史**：会话列表、回看以前的问答、删除会话。
- **时间一律按前端时钟显示**（2026-10-10 用户口径）：侧栏的「今天 / 昨天 + 时刻」按浏览器所在时区算，
  一轮的耗时由浏览器自己计时（从"我按下发送"到"看到结论"），不用服务端回的时间。后台跑的那一轮也一样：
  它的起点时刻随运行记着，回到页面接着往下算。
- **耗时单位随量级变**：`812ms` / `4.9s` / `1分52秒` / `1小时05分`（`src/lib/format-units.ts`，界面上唯一出口）。
- **token 分两个数说**：`上下文 5.0k · 输出 239 tokens`（最后一步这次模型的用量 = 它当时看到的上下文有多大）
  与 `累计 1.1M`（所有步相加，工具循环每步都会重发上下文，这是计费口径）—— 只显示累计会让人以为模型一次返回了上百万 token。
- **回答完画面不消失、历史即时可见**：一轮落库时它的对话 id 从"新对话"变成真 id，
  画面按"发起时归属的那段对话 + 落库后属于哪段"两个键认，落库即刷侧栏。
- **自定义系统提示词**：问答配置里可改，界面显示默认提示词。
- **工具开关（按本体）**：全局默认一份，某个本体可以单独覆盖；关掉的工具模型与外部 MCP 客户端都拿不到，
  MCP 调试页里灰着显示，并写明当前是「跟随全局默认」还是「本体 X 单独配置」，可一键回到跟随全局。

### 工具集

| 工具 | 做什么 |
| --- | --- |
| `search_schema` | 语义检索：支持一次传多个关键词，按概念去重并标出各关键词命中的概念；名字 / 说明 / 取值三类命中，命中结果直接带"落点"（绑定的表、来源列、挂在哪个对象类型下），拿到就能写 SQL |
| `get_object_type` | 对象类型详情：支持一次传多个对象类型；返回每个对象类型的完整属性、主键、绑定的数据来源、一跳关系类型与动作、实现的接口 |
| `list_concept_groups` | 概念分组清单 |
| `list_interfaces` | 接口清单 |
| `traverse_object_types` | 对象类型多跳查询：默认 3 跳 / 最多 5 跳，可限定类型与方向，不限定时走全图 |
| `list_actions` | 动作定义 |
| `list_metrics` | 指标定义 |
| `get_table_ddl` | 支持一次传多张表，分别返回完整表结构 + 列画像 + 这张表被哪些对象类型绑定 |
| `run_sql` | 只读查询：词法闸门 + 只读事务，默认 100 行上限、超了在结果里写明"已截断" |
| `query_object_instance` / `query_instance_subgraph` | 按类型取对象、取关系子图（这一版只在对象类型 / 关系类型这一层推理，这两个默认停用，界面上灰着） |

- `search_schema` 的检索面：对象类型名、说明、分组、绑定的表、属性名、**属性说明**、接口名与实现方、指标名与口径。
  打分：名字完全一致 100 / 包含 70 → 列取值命中 45 → 描述命中 30 → 长问题退回按词命中；
  不传 `kinds` 时对象类型 / 指标 / 关系类型保底占一半名额，属性不会刷屏。
- **表只能通过对象类型到达**：`list_tables` / `search_columns` 按用户口径没有实现。

### 工具输出约定

工具结果是喂给模型的，token 花在这里就等于花在每一次推理上，所以有明确的取舍口径（详见 `AGENTS.md`）：

- **紧凑 JSON**，不缩进（同一张表 16,276 → 10,536 字符）。
- **同一信息不重复出现**：`run_sql` 只在语句被平台改写时才回显 `executed_statement`。
- **列名 + 位置数组**：`run_sql.rows`、`traverse_object_types.nodes / edges`、`get_table_ddl.bound_object_types`、
  `column_profile.columns` 都按固定列序给数组，列序写进工具说明并有单测钉住。
- **表结构把注释内联进列定义**，不再另发 `COMMENT ON`；类型补长度 / 精度（`VARCHAR2(2000)`、`NUMBER(15,2)`）。
- **只减 token、不减信息**：真超上限时写明"原长多少、截到哪里"，不静默截断。
- **列清单不设上限、不砍尾巴**（2026-10-10 用户口径）：`get_table_ddl` 的映射列清单、对话历史列表、
  列画像的日期覆盖都**默认给全**（这些是定义层/清单，条数由表结构与用户自己的积累决定：实测 51 列只占 0.65KB）。
  按分数排序的 `search_schema` 是检索不是清单（一条命中带 detail，实测 234 字符/条，"用户"这种词命中 583 条 = 183KB），
  所以它默认给前 50 条、最多能要到 1000 条，并在返回里写明 `total_matched` 与被省掉的 `omitted` —— 尾巴可以不给，绝不隐形。
- 工具会回耗时，便于判断哪次查询贵。

## MCP 服务

左侧「能力验证 → MCP 调试」。**两个服务端，职责与鉴权都不同，别混：**

| | `/api/mcp` | `/api/skills/mcp` |
| --- | --- | --- |
| 发什么 | 本体数据（对象类型 / 关系类型 / 动作 / 指标 …） | 建模方法（三套技能的 Markdown） |
| 鉴权 | `Bearer`：平台会话令牌 或 MCP 访问令牌 | **无**（免令牌，内容只是仓库里的公开文档） |

- **两个地址**：
  - 平台级 `/api/mcp`：一个端点覆盖所有本体，查哪个由每次调用的 `ontology_id` 决定；
  - 本体级 `/api/mcp/<本体 id>`：**钉死在一个本体上** —— 工具清单按这个本体的开关给，调工具时自动用它，
    模型不用也不该自己填 id，配置片段一眼看出查的是谁。
- **访问令牌**：界面上生成 / 查看 / 撤销，**可以有多条**（一条配一个客户端或一台机器，撤销哪条只断哪条）。
  明文加密存平台库，只有 ADMIN 能动；`.env.local` 的 `MCP_API_TOKEN` 仍然认，作为一条只读兜底。
  令牌清单在专用弹窗里管，「MCP 接入」页只留一行摘要 + 入口。
- **MCP 调试页**分两档：工具（逐个小试，跑的是真实 MCP 协议）+ MCP 接入（地址、作用域切换、各客户端配置片段、
  令牌管理）。配置片段默认给「当前本体」那条地址，看过令牌之后片段里带的就是真值。

## 数据资源

左侧「平台 → 数据资源」。

- PostgreSQL / MySQL / Oracle 三种关系库的连接管理（凭据加密保存）、表 / 视图浏览、
  结构缓存（查一次存平台库，手动刷新才回源）、连接池与并发闸门、只读 SQL 闸门（词法 + 只读事务）。
- **列画像**：每列采样 1000 行后的取值种数、空值比例，低基数列直接给取值清单（例如用户状态 = 未停机 / 报暂停 / 欠费停 …）。
  成本红线：只对**被对象类型绑定的表**做、只采样不精确统计、取值种数 >50 按高基数列处理、结果**按天复用**，
  `refresh: true` 才重采。
- **对象类型绑定数据来源**：主来源决定身份与标题，补充来源按主键补齐属性；一个对象类型可以挂多份来源。
  对象页会主动提示"还差绑定的来源"，并给一个能直接去补的入口。

## 本体技能与出包

左侧「本体模型 → 本体技能」。

- **三套建模技能**：需求澄清 → 本体设计 → 出包交付。页面上只给清单（名称 / 适用场景 / 主要产物），
  正文不进页面，**只支持整体下载 zip**，解压进 `~/.codex/skills/` 或 `~/.agents/skills/` 就能用。
- 同一套技能**也发布为免令牌 MCP**（`/api/skills/mcp`），客户端里就是斜杠命令；工具名自带
  `ontology_build_skill`，与查本体数据那套一眼分得开。
- **出包走「清单 → 编译」**：模型只写结构化清单（引用一律写名字，不写 UUID），
  脚本 `skills/ontology-bundle/scripts/build-bundle.mjs` 负责解析引用、生成 id、补默认值，
  产出的就是平台能直接导入的本体包。Windows / Linux / macOS 同一套命令。
- **本体包**：导出 / 导入 `.ontology.json`（`format: ontology.bundle`）。
- **bkn 知识网络导入**：对象类型、关系类型、概念分组、指标自动转换，认不下的（如 `mapping_rules`）逐条列出。
- **命令行导入**：`node scripts/import-ontology.mjs <文件.json>` 一条命令导完（登录 → 挑存储 → 导入），
  支持 `--dry-run` 先干跑、`--name` 改名、`--publish` 直接发布。1MB / 52 个对象类型的文件实测约 1 秒。

## 平台与交付

左侧「平台 → 设置」。

- **登录与鉴权**：登录（`POST /api/auth/login`）回一枚**平台会话令牌**，之后每个请求带
  `Authorization: Bearer <令牌>`；令牌是 8 小时过期的 JWT，服务端每次请求都回库核对用户
  （删用户 / 改权限立刻生效）。**不用会话 Cookie** —— 所以 Postman / curl / 脚本直接就能调，
  不用再回浏览器里抄凭据。Swagger `/docs` 上点右上角 Authorize 粘一次令牌即可 Try it out。
- **用户与角色（RBAC）**：权限是 **13 个权限点**（按模块分组：本体模型 / 本体实例 / 数据资源 / 能力验证 / 平台），
  角色 = 一组权限点。内置三档 **管理员 · 编辑者 · 查看者**（不可改不可删，要定制就新建角色），
  也可以自建角色；**`admin` 永远是全部权限**。入口在「设置 → 用户与角色」：
  建账号（管理员直接给初始密码）、改角色、重置密码、停用、删除。
  删除是真删 —— 他历史的审计记录会保留、只是"操作人"变空（另有一条 `USER_DELETED` 记着邮箱）。
  最后一个能管用户的账号不许降级 / 停用 / 删除。权限不足返回 **403**（不是 401，也不是 400）。
- **界面可见性跟着角色走**：左侧导航每一项都绑一个权限点，没权限的功能**不出现在导航里** ——
  总览 / 本体建模 / 本体技能 / 动作 / 规则 = 本体模型；实例图谱 / 对象 / 关系 = 本体实例；
  智能问答 / MCP 调试 = 能力验证；数据资源（查看数据资源）。「设置」所有人可见，里面三个标签再各自判
  （图引擎配置 = 图引擎连接、审计记录、用户与角色）。当前视图没权限时自动落到第一个能进的页面，不留空白页。
  **没有图引擎连接权限的角色照样能看本体**：本体列表自带落点信息，总览与本体建模正常使用
  （以前 `/api/targets` 的 403 会把本体列表一起带空 —— 新账号看着像「平台里没有本体」）。
- **平台库**：TypeORM + 迁移（业务代码不写 SQL），启动自动建表、自动创建首个管理员。
- **图存储抽象**：内置后端（平台自带，PG 持久化快照）与 **Apache Jena / Fuseki**（可选外部）共存，Neo4j 已整体移除。
- **审计日志**：发布、动作决策、数据资源与工具开关、MCP 令牌的变更都落库。
- **OpenAPI 文档**：`/docs`（Swagger UI，构建时自动生成）。
- **Docker Compose 部署**：只部署本体平台 + PostgreSQL；Fuseki 不是必需项（要用就作为外部图引擎接进来）。
- `docs/architecture.html`：架构图（中英并排模块名 + 存储清单）。

## 明确还没做的（避免误会）

- `get_property_values`（按列的取值查询工具）—— 用户明确"先不做"，取值走列画像。
