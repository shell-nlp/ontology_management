# 实体与关系属性编辑设计

## 目标

在实体和关系管理页中，用户点击一条现有数据后可在固定右侧详情面板查看并编辑属性值。编辑不改变实体类型、关系类型、关系端点或图数据的标识；所有修改以显式“保存属性”提交到 Neo4j。

## 已确认约束

- 本体以草稿维护，校验通过后发布；实体和关系实例只能使用已发布类型。
- 一个实体实例只对应一个已发布实体类型和 Neo4j Label；关系实例必须符合已发布关系类型及其起始、终止实体类型契约。
- 属性定义属于实体类型或关系类型，属性值属于实例。首版支持文本、整数、小数、布尔值、日期、日期时间、文本数组和 JSON。
- 管理员可以编辑实例属性，查看者只能浏览。
- Neo4j 目标凭据密文保存在 PostgreSQL 的 `ontology_platform` Schema；数据库操作只在 Next.js 服务端执行。
- 本次不提供删除实例、修改实体 Label、修改关系 Type 或重连关系端点的功能。

## 交互设计

桌面端实体页和关系页采用固定双栏布局：左栏列出目标 Neo4j 中最多 100 条实例；点击一行后右栏出现详情与编辑面板。实体行显示 Label 和属性摘要，关系行显示 Type、起始实体与终止实体。当前选中行具有明确高亮。

右栏显示不可编辑的 `elementId`、类型信息和端点信息。属性字段按已发布本体的定义生成：布尔值用开关，日期和日期时间用相应输入控件，JSON 用文本域，其余基础类型用文本或数字输入。保存前客户端解析本地输入，保存时服务端再次验证，成功后刷新左栏和详情摘要。失败时保留表单值并显示字段级或操作级错误。

窄屏下，详情面板退化为覆盖列表的抽屉；保存、取消与错误展示保持一致。

## 服务端设计

新增两个管理员专用的 `PATCH` 路由：

- `/api/instances/entities/:elementId` 仅接收 `{ properties }`；路径参数唯一标识待更新实例。路由读取目标的已发布实体类型，验证字段集合、必填属性和数据类型后，执行 `MATCH (n) WHERE elementId(n) = $elementId SET n += $properties`。
- `/api/instances/relationships/:elementId` 接收同样的请求结构，读取关系实例 Type 对应的已发布关系类型，验证后执行 `MATCH ()-[r]->() WHERE elementId(r) = $elementId SET r += $properties`。

两个路由都必须验证目标存在、会话角色为管理员、实例存在且实例类型属于目标的已发布本体。它们不得接受 Cypher 片段、Label、关系 Type 或端点 ID 的变更。响应返回更新后的标准化实例记录，供前端直接刷新选中状态。

## 前端数据流

实体和关系管理器加载列表后维护 `selectedId` 与一份独立的 `draftProperties`。点击行仅更新选择状态，不写入数据库；用户修改字段只更新 `draftProperties`；点击保存才调用对应 `PATCH` 接口。响应成功时以返回记录替换列表项并更新详情；响应失败时保留 `draftProperties`。

当目标尚未选择或未发布本体时，页面显示原因并禁用创建与编辑。选中记录被后台刷新移除时，清空选择并提示记录已不存在。

## 错误处理

- 无管理员角色：返回 403，前端禁用保存按钮。
- 目标、实体或关系不存在：返回 404，并清除当前选择。
- 未发布本体、实例类型未受管或关系契约失效：返回 422，并展示具体原因。
- 属性名未定义、必填属性缺失或值类型不符：返回 422，包含字段名和错误说明。
- Neo4j 连接或执行错误：返回 400，前端保留用户输入以便重试。

## 验收标准

1. 点击实体或关系行会选中该行，并在右侧显示真实 `elementId`、类型和当前属性值。
2. 管理员修改属性并点击保存后，Neo4j 中对应节点或关系属性被更新，列表与详情同步刷新。
3. 查看者看不到可用的保存入口，直接调用更新接口返回 403。
4. 不能通过编辑接口修改 Label、关系 Type 或关系端点。
5. 未定义字段、缺少必填属性和类型不符的值均被拒绝且不写入 Neo4j。
6. 窄屏中详情以抽屉展示，不遮挡保存与取消操作。
