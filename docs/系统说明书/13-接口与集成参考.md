# 第 13 章 · 接口与集成参考

## 13.1 接口总则

平台对外的 HTTP 接口是 Next.js App Router 实现，业务逻辑集中在 `src/lib`，路由只做薄封装。集成时遵循：

- REST 接口用于平台界面和脚本；
- 智能问答与 MCP 使用独立的流式 / JSON-RPC 协议；
- 所有接口默认要求登录，除非明确标注公开；
- 写操作有权限点校验；
- 读接口默认只读已发布版本，除非明确允许草稿版本；
- 接口字段的最终事实来源是 `/docs`（Swagger UI）与代码里的 Zod schema。

## 13.2 鉴权

```http
Authorization: Bearer <平台会话令牌>
```

| 接口 | 鉴权方式 |
| --- | --- |
| `/api/auth/login` | 公开；用邮箱密码换会话令牌 |
| `/api/bootstrap` | 仅首次初始化兼容入口 |
| 其它 REST | Bearer 平台会话令牌 |
| `/api/mcp`、`/api/mcp/<本体 id>` | Bearer 平台会话令牌或 MCP 访问令牌 |
| `/api/skills/mcp` | 免令牌（公开技能文档） |

状态码：

| 状态码 | 含义 |
| --- | --- |
| `401` | 未登录、令牌过期或用户已失效 |
| `403` | 已登录但缺少权限点 |
| `400` | 请求参数或业务规则不合法 |
| `404` | 资源不存在 |
| `409` | 状态冲突，例如图存储被占用、只有草稿可以写 |
| `500` | 服务端未分类错误 |

错误响应一般是：

```json
{ "error": "人话错误信息" }
```

接口文档：

```text
GET /docs          Swagger UI
GET /openapi.json  OpenAPI 规范
```

## 13.5 本体模型与版本

“本体模型”是对象类型、关系类型、接口、指标、动作、规则以及草稿 → 校验 → 发布 → 激活。

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` / `POST` | `/api/ontology` | 读 / 写 | 版本列表 / 创建草稿 |
| `PATCH` | `/api/ontology/:versionId` | `ontology.write` | 更新草稿定义 |
| `DELETE` | `/api/ontology/:versionId` | `ontology.version.delete` | 删除草稿或历史版本；当前生效版本返回 `409` |
| `POST` | `/api/ontology/:versionId/validate` | `ontology.publish` | 校验草稿 |
| `POST` | `/api/ontology/:versionId/publish` | `ontology.publish` | 发布并重建图 |
| `POST` | `/api/ontology/:versionId/activate` | `ontology.publish` | 激活历史快照 |
| `GET` / `POST` | `/api/ontology/:versionId/actions` | 读 / `instance.write` | 动作决策预览 / 执行动作（可带写回业务库） |
| `GET` | `/api/ontology/:versionId/decisions` | `instance.read` | 当前草稿的动作决策记录 |

> `GET /api/ontology/:versionId` 不在当前路由中；读取版本定义走版本列表和快照接口。以 OpenAPI 为准。

动作执行请求体（`POST /api/ontology/:versionId/actions`）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `actionId` | 是 | 动作 id |
| `subjectEntityId` / `subjectRef` | 否 | 主对象（`subjectRef` 形如 `对象类型/主键串`；对象只存在于数据源时，平台先按主键把它取进草稿再执行） |
| `inputs` | 否 | 入参：`{ code, entityId?, entityRef?, value? }` |
| `dryRun` | 否（默认 `true`） | 只算不写：不改草稿快照，**也永远不写业务库** |
| `writeback` | 否（默认 `false`） | 是否把改动写回业务库（只对**表 / 视图主来源**生效；干跑时只产出"会写什么"的计划） |

- 写回只支持改**已有行**（UPDATE），按对象类型主来源的主键列定位；键命中 0 行或 2 行以上一律拒绝（不盲写）。
- 一次动作里只要有一处写不回去，返回 `409` 且**整批不执行**，响应里带逐条原因与出路。
- 响应里的 `writeback` 分四态：`OFF`（没勾）/ `PREVIEW`（干跑出的计划）/ `APPLIED`（已写库，带旧值 → 新值与实际语句）/ `REFUSED`（被拒，整批没执行）。

写回示例：

```bash
curl -s -X POST http://localhost:3000/api/ontology/<versionId>/actions \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"actionId":"<id>","subjectRef":"专线产品用户/371","dryRun":false,"writeback":true,"inputs":[]}'
```

创建草稿示例：

```bash
curl -s http://localhost:3000/api/ontology \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"targetId":"<target-id>","definition":{...}}'
```

发布示例：

```bash
curl -s -X POST http://localhost:3000/api/ontology/<versionId>/publish \
  -H "Authorization: Bearer $TOKEN"
```

## 13.8 只读查询

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/api/query` | `instance.read` | 执行只读 SPARQL；写入一律拒绝 |

该接口面向图存储，与查询 DSL 不是同一条链路。智能问答在 `run_query` 打开时优先走本体 SQL；通过 ODS 或数据资源只读连接器执行，不再读取对象物化副本。`run_sql` 走数据资源只读 SQL，作为 DSL 不支持或排障时的兜底。

## 13.14 集成建议

| 场景 | 推荐路径 |
| --- | --- |
| 脚本批量导入本体 | `scripts/import-ontology.mjs` + `--dry-run` |
| 外部 Agent 查本体 | 本体级 MCP `/api/mcp/<本体 id>` + 独立访问令牌 |
| 平台内调试 MCP | “MCP 调试”页，使用会话令牌 |
| 前端集成 | REST + Bearer；会话、对象、问答都有对应接口 |
| 只读数据查询 | 优先让模型走工具；平台外部集成用 MCP，不直接拿业务库连接。结构化问数走 `run_query`（查询 DSL，出厂默认关闭，需在「MCP 调试」里打开），`run_sql` 作为兜底与排障保留 |
| 监控发布状态 | 审计 `VERSION_PUBLISH_*` + 图引擎连接测试 |
| 监控问答 | `/api/reasoning/status` + 审计 `REASONING_RUN` |

## 13.15 契约维护

- 改接口字段、状态码或权限点时，同步更新本章与 OpenAPI schema；
- 新增模块时，在 Swagger 分组里给中文名，并在本表补一行；
- 不把内部实现细节（图库语句、密钥、物理列）暴露给外部客户端；
- 流式接口的断连语义要在协议层说清楚：断开 ≠ 取消，取消只认 cancel；
- 工具名、工具分组、工具标题在 `src/lib/reasoning/mcp.ts` 里集中登记，改工具名必须同时更新工具目录、MCP 分组、步骤摘要与测试。
