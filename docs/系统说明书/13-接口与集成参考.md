# 第 13 章 · 接口与集成参考

## 13.1 接口总则

平台对外的 HTTP 接口是 Next.js App Router 实现，业务逻辑集中在 `src/lib`，路由只做薄封装。集成时遵循：

- REST 接口用于平台界面和脚本；
- 智能问答与 MCP 使用独立的流式 / JSON-RPC 协议；
- 所有接口默认要求登录，除非明确标注公开；
- 写操作有权限点校验；
- 读接口默认只读已发布版本，除非明确允许草稿版本；
- 接口字段的最终事实来源是 `/docs`（Swagger UI）与代码里的 Zod schema。

## 13.2 鉴权

```http
Authorization: Bearer <平台会话令牌>
```

| 接口 | 鉴权方式 |
| --- | --- |
| `/api/auth/login` | 公开；用邮箱密码换会话令牌 |
| `/api/bootstrap` | 仅首次初始化兼容入口 |
| 其它 REST | Bearer 平台会话令牌 |
| `/api/mcp`、`/api/mcp/<本体 id>` | Bearer 平台会话令牌或 MCP 访问令牌 |
| `/api/skills/mcp` | 免令牌（公开技能文档） |

状态码：

| 状态码 | 含义 |
| --- | --- |
| `401` | 未登录、令牌过期或用户已失效 |
| `403` | 已登录但缺少权限点 |
| `400` | 请求参数或业务规则不合法 |
| `404` | 资源不存在 |
| `409` | 状态冲突，例如图存储被占用、只有草稿可以写 |
| `500` | 服务端未分类错误 |

错误响应一般是：

```json
{ "error": "人话错误信息" }
```

接口文档：

```text
GET /docs          Swagger UI
GET /openapi.json  OpenAPI 规范
```

## 13.3 认证与初始化

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/bootstrap` | 创建 Schema 与首个管理员（仅一次；自动初始化后返回 409） |
| `POST` | `/api/auth/login` | 登录，响应体含 `token` 与 `expiresInSeconds` |
| `POST` | `/api/auth/logout` | 空操作；前端丢弃令牌 |
| `GET` | `/api/auth/session` | 当前会话用户 |
| `POST` | `/api/auth/password` | 修改自己的密码（校验当前密码） |

登录示例：

```bash
curl -s http://localhost:3000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"******"}'
```

响应关键字段：

```json
{
  "id": "...",
  "email": "admin@example.com",
  "roleId": "admin",
  "roleName": "管理员",
  "permissions": ["ontology.read", "..."],
  "token": "<JWT>",
  "expiresInSeconds": 28800
}
```

## 13.4 本体管理

“本体管理”是本体这个实体本身的增删改查，不是“本体模型”。

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` / `POST` | `/api/ontologies` | 读 / 写 | 本体列表 / 新建本体 |
| `GET` / `PATCH` / `DELETE` | `/api/ontologies/:ontologyId` | `ontology.read` / `ontology.write` / `ontology.publish` | 查看 / 修改 / 删除本体档案 |
| `GET` / `POST` | `/api/ontologies/:ontologyId/bind-sources` | 读 / 写 | 查看待补绑定 / 提交数据资源绑定 |
| `GET` | `/api/ontologies/:ontologyId/export` | `ontology.read` | 导出本体包 |
| `POST` | `/api/ontologies/import` | `ontology.write` | 导入本体包或 bkn |

## 13.5 本体模型与版本

“本体模型”是对象类型、关系类型、接口、指标、动作、规则以及草稿 → 校验 → 发布 → 激活。

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` / `POST` | `/api/ontology` | 读 / 写 | 版本列表 / 创建草稿 |
| `PATCH` | `/api/ontology/:versionId` | `ontology.write` | 更新草稿定义 |
| `POST` | `/api/ontology/:versionId/validate` | `ontology.publish` | 校验草稿 |
| `POST` | `/api/ontology/:versionId/publish` | `ontology.publish` | 发布并重建图 |
| `POST` | `/api/ontology/:versionId/activate` | `ontology.publish` | 激活历史快照 |
| `GET` / `POST` | `/api/ontology/:versionId/actions` | 读 / `instance.write` | 动作决策预览 / 执行动作 |
| `GET` | `/api/ontology/:versionId/decisions` | `instance.read` | 当前草稿的动作决策记录 |

> `GET /api/ontology/:versionId` 不在当前路由中；读取版本定义走版本列表和快照接口。以 OpenAPI 为准。

创建草稿示例：

```bash
curl -s http://localhost:3000/api/ontology \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"targetId":"<target-id>","definition":{...}}'
```

发布示例：

```bash
curl -s -X POST http://localhost:3000/api/ontology/<versionId>/publish \
  -H "Authorization: Bearer $TOKEN"
```

## 13.8 只读查询

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/api/query` | `instance.read` | 执行只读 SPARQL；写入一律拒绝 |

## 13.13 平台管理

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` / `POST` | `/api/users` | `users.manage` | 用户列表 / 新建 |
| `PATCH` / `DELETE` | `/api/users/:userId` | `users.manage` | 改角色 / 重置密码 / 停用 / 删除 |
| `GET` / `POST` | `/api/roles` | `users.manage` | 角色列表（含权限点）/ 新建角色 |

| `GET` | `/api/audit` | `audit.read` | 审计记录；范围 `changes` / `actions` / `reads` / `all` |

审计查询参数：

- `scope=changes|all|actions|reads`，默认 `changes`；
- `action=` 单个审计动作码；
- `targetId=` / `actorId=` / `from=` / `to=`（ISO 时间）；
- `limit=` 默认 50，上限 200；`offset=` 分页。

## 13.14 集成建议

| 场景 | 推荐路径 |
| --- | --- |
| 脚本批量导入本体 | `scripts/import-ontology.mjs` + `--dry-run` |
| 外部 Agent 查本体 | 本体级 MCP `/api/mcp/<本体 id>` + 独立访问令牌 |
| 平台内调试 MCP | “MCP 调试”页，使用会话令牌 |
| 前端集成 | REST + Bearer；会话、对象、问答都有对应接口 |
| 只读数据查询 | 优先让模型走工具；平台外部集成用 MCP，不直接拿业务库连接。查询 DSL 的关系 JOIN 与同资源 MDO JOIN 已实现，但 `run_query` 仍关闭 |
| 监控发布状态 | 审计 `VERSION_PUBLISH_*` + 图引擎连接测试 |
| 监控问答 | `/api/reasoning/status` + 审计 `REASONING_RUN` |

## 13.15 契约维护

- 改接口字段、状态码或权限点时，同步更新本章与 OpenAPI schema；
- 新增模块时，在 Swagger 分组里给中文名，并在本表补一行；
- 不把内部实现细节（图库语句、密钥、物理列）暴露给外部客户端；
- 流式接口的断连语义要在协议层说清楚：断开 ≠ 取消，取消只认 cancel；
- 工具名、工具分组、工具标题在 `src/lib/reasoning/mcp.ts` 里集中登记，改工具名必须同时更新工具目录、MCP 分组、步骤摘要与测试。
