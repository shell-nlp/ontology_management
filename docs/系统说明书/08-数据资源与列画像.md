# 第 8 章 · 数据资源与列画像

## 8.1 数据资源和本体存储不是一回事

这是平台里最容易混淆的一组概念：

| 概念 | 回答的问题 | 入口 | 存什么 |
| --- | --- | --- | --- |
| 数据资源 | 对象的业务数据从哪张表来？ | 平台 → 数据资源 | 外部关系库的连接与结构缓存 |
| 本体存储 / 图引擎连接 | 发布后的本体落在哪个图库？ | 设置 → 图引擎配置 | 内置图或 Jena/Fuseki 连接 |

简单说：

- **数据资源**是业务系统的事实来源，平台只读访问；
- **本体存储**是本体发布后的投影，平台可重建；
- 两者可以分别配置，但对象类型只有在绑定数据资源之后才能回源取数、物化索引和做列画像。

## 8.2 支持的数据来源

当前支持三种关系库：

| 类型 | 连接形态 | 容器 | 默认端口 |
| --- | --- | --- | --- |
| PostgreSQL | 主机 + 端口 + 数据库 + 模式 | 模式（schema），可留空 | 5432 |
| MySQL | 主机 + 端口 + 数据库 | 库名即容器 | 3306 |
| Oracle | 主机 + 端口 + 服务名 + 模式 | 模式 / 用户，可留空 | 1521 |

规划中的非关系来源包括 Elasticsearch、REST 接口、文件集合；它们**当前不可用**，不要在实施计划里当作已交付能力。

Oracle 兼容性提示：

- Oracle 11g 及更早的服务端需要 Thick 模式；
- Docker 镜像已内置 Linux Instant Client，并把 `ORACLE_CLIENT_LIB_DIR` 指向 `/opt/oracle/instantclient`；
- 源码运行时需要自行提供 Instant Client 目录；
- 结构清单走数据字典（`all_tables`、`all_tab_columns` 等），不依赖 ORM 的 `getTables()`。

## 8.3 登记数据资源

入口：**平台 → 数据资源**。

### 操作步骤

1. 点“新建数据资源”，选择类型（PostgreSQL / MySQL / Oracle）。
2. 填写连接字段：主机、端口、数据库 / 服务名、模式、用户名、密码。
3. 点“试连”。试连使用表单里的参数，不落库；确认能连再保存。
4. 保存后，在资源卡片上可以：
   - 测试已保存连接；
   - 浏览表与视图清单；
   - 查看字段结构和若干行数据预览；
   - 刷新结构缓存；
   - 编辑连接、启用/停用、删除。
5. 需要被对象类型绑定时，到本体建模的对象类型编辑里选择资源、表/视图和列映射。

### 凭据安全

- 数据资源密码使用 `TARGET_ENCRYPTION_KEY` 加密后保存；
- API 返回给前端的资源对象绝不包含密文或明文密码；
- 修改连接信息时，密码留空表示不修改；
- 换掉 `TARGET_ENCRYPTION_KEY` 会导致已有密文解不开，必须重新登记连接。

## 8.4 表 / 视图浏览与结构缓存

### 结构清单

`GET /api/data-sources/:sourceId/views`：

- `schema=*` 表示看全库所有模式；
- `search=` 按表名过滤；
- `limit=` 返回条数上限（缓存里最多 5000 条）；
- `refresh=1` 强制回源库重读，否则默认读平台库里的缓存。

返回里带 `fetched_at` 和 `from_cache`，界面可以明确告诉你这份结构是什么时候读回来的。

### 单表结构与预览

`GET /api/data-sources/:sourceId/views/:viewName`：

- 返回字段名、类型、是否可空、主键、唯一、注释、序号；
- 返回若干行数据预览（只读）；
- 同样支持 `refresh=1`；预览行数会进缓存键，20 行和 100 行是两份不同快照。

### 两层缓存

| 层 | 行为 | 失效时机 |
| --- | --- | --- |
| 服务端 | 结构清单按“连接 + 容器”缓存 60 秒，命中时不建连接、不查库 | 超过 60 秒，或请求带 `refresh=1` |
| 前端 | 资源清单、结构清单、字段与预览按 key 存在会话内存 | 改连接信息（整条丢弃）、超出缓存条数上限、整页刷新 |

单表读取走精确路径：Oracle 按 `owner + 表名` 定位，再取列与预览，不为了看一张表扫整库。

## 8.5 把对象类型绑定到数据资源

绑定写在对象类型上，而不是逐个对象上。参照 Palantir 的模型：

| 绑定项 | 含义 |
| --- | --- |
| 数据资源 + 表 / 视图 | 这份来源读哪张表 |
| 主键字段（可复合） | 主来源里，这几列构成一个对象的身份 |
| 显示名字段 | 对象在列表与图谱上的标题 |
| 属性映射 | 类的属性取自哪一份来源的哪个列 |

### 单来源绑定

1. 打开对象类型编辑。
2. 选择数据资源。
3. 选择 schema / 表或视图。
4. 从表字段中选择主键列；可多列构成复合主键。
5. 选择展示属性对应的列。
6. 为每个属性选择来源列；不映射的属性表示暂时不取数。
7. 保存草稿。

### 多来源绑定（column-wise MDO）

一个对象类型可以挂多份来源：

- `sources[0]` 是**主来源**：决定对象身份和标题；
- 后续来源是**补充来源**：主键列按顺序与主来源的主键列一一对齐，作为连接条件，用来补齐属性；
- 属性通过 `sourceId` 指回来源，通过 `sourceField` 指向具体列；
- 补充来源连接键的列数必须和主来源主键列数一致，否则拦发布。

### 校验口径

| 情况 | 处理 |
| --- | --- |
| 补充来源选了表却没有连接键、连接键列数和主键对不上、属性指向一份已不在对象类型上的来源 | 拦发布，配置自相矛盾 |
| 主来源未选表 / 未指定主键、补充来源未选表、同一张表挂两次 | 提醒，不拦发布；允许先搭结构 |

### 导入后的补绑定

从 bkn 或外部本体包导入时，来源可能只有 `SCHEMA.TABLE`，没有数据资源 id。导入后：

- 平台会按表名在本机资源里尽量自动匹配；
- 匹配不到的进入“待补绑定”清单；
- 用户在弹窗里逐个选资源，保存后写入草稿，不重新导入。

相关接口：`GET/POST /api/ontologies/:ontologyId/bind-sources`。

## 8.6 列画像

列画像解决的问题是：模型回答“状态正常的互联网专线”这类问题时，必须先知道某个列里到底有哪些取值、对应哪个码值。没有列画像时，模型只能一轮轮手写 `GROUP BY` 去探。

列画像不是精确统计，而是**低成本采样**。

### 采样规则

| 规则 | 数值 / 行为 |
| --- | --- |
| 采样范围 | 只对**被对象类型绑定的表**做；未绑定表不采 |
| 采样行数 | 前 1000 行（Oracle 用 `ROWNUM`，PG/MySQL 用 `LIMIT`） |
| 采样列数 | 单表最多 40 列，避免 SELECT 列表过长 |
| 低基数列 | 采样中取值种数 ≤ 50，直接给取值清单 |
| 高基数列 | 取值种数 > 50，按高基数列处理，不存取值 |
| 空值比例 | 记录采样中的空值比例 |
| 日期覆盖 | 对 DATE / DATETIME 列记录采样覆盖的日期范围与每日行数 |
| 缓存 | 写入 `column_profiles` 表，按天复用；默认 24 小时内直接读缓存 |

### 成本红线

- 不做全表 `COUNT(DISTINCT)`，因为 Oracle 大表上非常贵；
- 只采样、不精确统计；返回里必须如实写 `cached`、`sample_size` 和采样说明；
- 只有 `get_table_ddl` 带 `refresh: true` 或缓存过期时才回源库重采；
- 采样结果的 `distinct` 是采样里的取值种数，不是全表 distinct，不能当精确统计使用。

### 模型怎么用列画像

- `search_schema` 的取值命中会返回列画像里的取值，并给出落点 `bound_table` / `source_column` / `data_source`；
- `get_table_ddl` 会把列画像内联进表结构，模型拿到 DDL 就能看到码值与空值情况；
- 模型按“表只能通过对象类型到达”的原则使用数据，不直接枚举未绑定的表。

## 8.7 只读 SQL 护栏

平台不把业务库连接直接暴露给模型或前端；`run_sql` 与对象服务走同一套只读护栏。

### 词法闸门

- 语句必须以 `SELECT` / `WITH` / `SHOW` / `DESC` / `DESCRIBE` / `EXPLAIN` / `VALUES` / `TABLE` 开头；
- 语句里不能出现写操作关键字：`INSERT`、`MERGE`、`UPSERT`、`TRUNCATE`、`DROP`、`ALTER`、`CREATE`、`RENAME`、`GRANT`、`REVOKE`、`CALL`、`EXEC`、`COMMIT`、`ROLLBACK`、`LOCK`、`INTO`、`OUTFILE`、`COPY` 等；
- 一次只允许一条语句，多语句用分号分隔会被拒绝；
- 注释和字符串字面量会在检查前剥离，防止利用注释绕过。

### 执行层保护

- PostgreSQL / MySQL / Oracle 各自开启只读事务；
- 驱动起不了只读事务时，返回 `read_only_transaction=false` 与警告，如实暴露风险；
- PostgreSQL 支持事务内 `statement_timeout`，MySQL 尝试 `MAX_EXECUTION_TIME`，Oracle 这一层没有等价开关；
- 行数上限全链路统一：默认 100 行，最大 5000 行，超过必须标 `truncated=true`，不静默截断。

## 8.8 常见操作

### 新增一个业务库

1. 平台 → 数据资源 → 新建。
2. 选择类型，填连接参数，先试连。
3. 保存后点“刷新结构”，确认能看到表和视图。
4. 打开某张表，确认字段和预览正常。
5. 到对象类型编辑里绑定这张表。

### 对象页提示“还差绑定的来源”

说明对象类型有来源记录，但 `dataSourceId` 为空或指向已不存在的资源。处理：

1. 打开对象类型编辑；
2. 重新选择数据资源；
3. 确认表 / 视图、主键、展示属性、属性映射；
4. 保存草稿并发布。

### 更新表结构缓存

- 服务端缓存：请求带 `refresh=1`，或等 60 秒；
- 前端缓存：在界面点“刷新结构”，或改一次连接信息让整条缓存失效；
- 列画像：只有 `get_table_ddl` 带 `refresh: true` 或超过 24 小时才会重采。

### 删除数据资源

删除前先确认：

- 没有对象类型绑定它；
- 没有关系类型的数据来源指向它；
- 删除后相关对象类型会变成“绑定缺失”，需要重新选择来源。

## 8.9 当前限制

- 只支持 PostgreSQL / MySQL / Oracle 三种关系库；Elasticsearch、REST、文件仍在规划。
- 平台只读访问业务库；动作执行结果不会回写业务库。
- 列画像是采样，不是精确统计；低基数值清单只适合做码值提示，不适合做严谨报表。
- 结构缓存有 60 秒服务端有效期；刚改完表结构时点一次“刷新结构”再操作。
- 未绑定对象类型的表不参与列画像，也不能通过模型工具直接枚举。
- 数据资源密码与 MCP 令牌依赖 `TARGET_ENCRYPTION_KEY`；换密钥必须重新登记。
