# 第 9 章 · 智能问答

## 9.1 智能问答是什么

智能问答是平台内让模型基于**已发布本体**回答业务问题的能力。它不是一个直接写 SQL 的聊天框，而是“模型选只读工具 → 工具读本体与数据 → 结果回灌 → 模型组织答案”的服务端工具循环。

核心特征：

- 只读：查询定义、表结构、业务数据和对象实例，不做写操作；
- 只认已发布版本：工具侧读定义时只读 `status = PUBLISHED`；
- 服务端运行：一轮问答由服务端跑，不挂在某条浏览器连接上；
- 工具可关：管理员可以按全局或按本体关闭某些工具；
- 运行有记录：问答、工具调用和证据进入历史与审计。

## 9.2 使用前提

| 前提 | 说明 |
| --- | --- |
| 已配置 LLM | `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 三项齐全；否则页面明确提示模型未配置 |
| 已有发布版本 | 工具只认已发布本体；没有发布版本时先发布一次 |
| 有权限 | 进入页面与调用工具需要 `reasoning.use` |
| 数据资源可读 | 要查业务数据时，对象类型必须绑定可连接的数据资源 |
| 工具已开启 | 某些工具出厂默认关闭，需要到 MCP 调试页按全局或按本体打开 |

检查模型是否配置：`GET /api/reasoning/status` 返回 `configured`、`model` 和 `endpoint`。

## 9.3 界面使用

入口：**能力验证 → 智能问答**。

| 区域 / 操作 | 说明 |
| --- | --- |
| 提问框 | 输入自然语言问题；支持多行 |
| 图片按钮 / 拖拽 | 附着图片一起提问；浏览器侧先压缩，历史里记录张数与尺寸 |
| 思考开关 | 控制是否请求模型输出思考过程；关闭后直接检索 |
| 发送 | 起一轮后台运行，界面立即显示“运行中” |
| 停止 | 真正中止这一轮；不点停止，切走只是“不看了” |
| 侧栏 | 会话列表；正在跑的会话标“运行中”，完成后进入历史 |
| 新对话 | 开启一段新对话；**不会**停止正在跑的那一轮，而是把它让到后台 |
| 问答配置 | 调整工具步数、工具结果上限、取数行数、历史轮数与系统提示词 |
| 工具轨迹 | 每一步显示工具名、入参、返回摘要、耗时；可展开看返回 |
| 证据 | 从工具结果抽出的对象、关系、对象类型、接口、指标等；有权限时可点回对象页 |
| 页脚元信息 | 模型、耗时、上下文 / 输出 token、累计 token、步数、工具次数、历史上下文 |

### 运行状态与画面

- 一轮问答在服务端后台运行；关页面、切页、刷新、按“新对话”都不会停它；
- 只有点“停止”才会真正取消；
- 正在跑的轮次会出现在对话历史里；完成后自动落进历史；
- 如果一轮已经落库，画面按“发起时归属的会话 + 落库后归属的会话”两个键认，不会因为落库而跳走或消失。

### 时间与 token 展示

- 耗时用浏览器时钟算，从“我按下发送”到“看到结论”；不用服务端时间显示；
- 时间单位随量级变：`812ms`、`4.9s`、`1分52秒`、`1小时05分`、`2天03小时`；
- token 分两个数：
  - `上下文 5.0k · 输出 239 tokens`：**最后一步这次调用**的用量，表示模型当时看到的上下文与写出的内容；
  - `累计 1.1M`：所有模型调用相加，工具循环每步都会重发上下文，这是计费口径。
- 旧运行记录没有“最后一步”字段时，只显示累计。

## 9.4 后台运行机制

平台把“起一轮”和“看这条流”拆开：

```text
POST /api/reasoning/runs
  → 服务端立刻返回 runId，后台开始跑
  → 浏览器用 GET /api/reasoning/runs/:runId/events?after=N 接上
  → 断开连接只是不看了，运行照常推进
  → POST /api/reasoning/runs/:runId/cancel 才是真正停止
```

相关接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/reasoning/runs` | 起一轮后台问答，返回 `runId` |
| `GET` | `/api/reasoning/runs?targetId=` | 当前本体上还在跑或刚跑完未落库的运行 |
| `GET` | `/api/reasoning/runs/:runId/events?after=N` | 接上这一轮（SSE，按游标补看 + 增量） |
| `POST` | `/api/reasoning/runs/:runId/cancel` | 停止这一轮 |
| `POST` | `/api/reasoning/stream` | 起一轮并就地看完（SSE，给脚本用） |
| `POST` | `/api/reasoning/run` | 非流式运行，给脚本与调试用 |

### SSE 事件

每一帧的形状是：

```text
data: {"i": 12, "e": { ...event... }}
```

事件类型：

| 事件 | 含义 |
| --- | --- |
| `thinking` | 思考文本增量 |
| `answer` | 正文文本增量 |
| `answerReset` | 这段文本其实是“要调工具”的过渡语，界面把它清出正文 |
| `step` | 一次工具调用与结果 |
| `context` | 多轮上下文准备状态：`start` / `compressing` / `ready` |
| `done` | 运行完成，带完整 `ReasoningRun` |
| `saved` | 落库完成，带对话 id；失败时带 warning |
| `error` | 运行失败 |

`after` 游标**包含端点**：游标那一条会重发一次，因为它可能刚被合并进更多文本。服务端先订阅再补看，避免正好在两步之间结束的运行漏掉 `done` / `saved`。

### 边界

- 运行登记在**内存**里；进程重启或容器重建会丢掉正在跑的运行，已经落库的历史不受影响；
- 服务端登记处保留已结束记录约 10 分钟，供刚跑完再接回；
- 取消只对正在跑的运行有效；
- 别人的运行一律按不存在处理；接口会校验运行归属。

## 9.5 工具集

智能问答与外部 MCP 共用同一套工具实现。工具全部只读。

### 9.5.1 默认开启的工具

| 工具 | 做什么 |
| --- | --- |
| `search_schema` | 语义检索对象类型、关系类型、动作、接口、指标与属性；支持多个关键词、名字/描述/取值三类命中，返回落点 |
| `get_object_type` | 对象类型详情：完整属性、主键、数据来源、一跳关系、动作、接口、指标；支持一次传多个类型 |
| `list_concept_groups` | 概念分组清单 |
| `list_interfaces` | 接口清单 |
| `traverse_object_types` | 对象类型多跳查询：默认 3 跳、最多 5 跳；可限定类型、方向和关系 |
| `get_table_ddl` | 一次可传多张表，返回完整表结构、列画像、反向引用（这张表被哪些对象类型绑定） |
| `run_sql` | 只读 SQL：词法闸门 + 只读事务，默认 100 行、最大 5000 行；支持 CTE 和子查询 |
| `list_metrics` | 指标定义清单 |

### 9.5.2 出厂默认关闭的工具

| 工具 | 做什么 | 为什么默认关 |
| --- | --- | --- |
| `list_actions` | 动作定义与规则 | 2026-10-09 用户口径：动作定义默认关闭 |
| `query_object_instance` | 按对象类型查真实对象实例 | 默认关闭，需要查具体对象时再开 |
| `query_instance_subgraph` | 按对象类型和关系类型取子图 | 默认关闭，需要关系子图时再开 |

这三个工具不是“没有实现”，而是出厂策略关闭；管理员可以在“MCP 调试”里按全局默认或按本体单独打开。

### 9.5.3 平台永久关闭的工具

| 工具 | 状态 |
| --- | --- |
| `run_query` | `disabled: true`，当前不开放给模型与外部客户端；关系 JOIN 与同一数据资源内的 MDO JOIN 已实现 |

查询 DSL 的解析器、关系 JOIN、基数保护、同一数据资源内的 MDO JOIN 和执行器已经实现，详见 [查询 DSL](./查询DSL.md)；但 `run_query` 工具仍处于平台永久关闭状态，现有问答走 `run_sql`。跨数据资源 JOIN 仍不支持；影子对拍工具已实现，真实业务问题集对拍与验收仍在推进。

### 9.5.4 MCP 专用工具

| 工具 | 说明 |
| --- | --- |
| `list_ontologies` | 只有外部 MCP 平台级端点需要：先列出本体拿 `ontology_id`，再查其它工具；默认开启 |

### 9.5.5 工具输出约定

工具结果是喂给模型的，token 花在这里会影响每一次推理，因此有明确约定：

- 紧凑 JSON，不缩进；
- 同一信息不重复出现；
- 列表按固定列序用位置数组表示，列序写进工具 description 并有单测；
- 表结构把注释内联进列定义；
- 真超上限时写明“原长多少、截到哪里”，不静默截断；
- 列清单（映射列、字段清单、对话历史、列画像日期覆盖）默认给全；
- 检索类结果默认前 50 条、最多 1000 条，并返回 `total_matched` / `omitted`；
- 工具会返回耗时，便于判断哪次查询贵。

## 9.6 问答配置

配置抽屉只影响“结论完不完整 / 口味”，保护数据库的只读事务和超时不在其中，也不能被关掉。

| 配置 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 工具步数上限 | 1～100 | 不限制（服务端兜底 100） | 一次问答最多让模型走几步 |
| 工具结果上限 | 500～200000 字 | 不限制 | 单工具返回超过就截断并提示 |
| 取数行数上限 | 1～5000 | 不限制 | `run_sql` 一次最多返回多少行；不指定时默认 100 |
| 历史轮数 | 0～20 | 默认 5 | 最近几轮原样回放；0 = 不带历史；更早的压成摘要 |
| 系统提示词 | ≤20000 字 | 内置默认 | 留空或与默认一致就走默认提示词 |

配置存在浏览器本地，一台机器一套，不跟账号走。服务端仍会做兜底限制，防止死循环或一次拉爆内存。

## 9.7 多轮上下文与图片

### 多轮上下文

- 最近若干轮原样回放，带工具轨迹与证据；
- 更早的轮次压成摘要，不会直接丢；
- 界面显示“上下文 N 轮 · 已压缩 M 轮”；
- 压缩失败只记 warning，不把整轮问答抛掉；
- 历史轮数设为 0 时回到单轮问答。

### 图片输入

- 提问可以附带图片；浏览器侧先压缩；
- 图片以 data URL 形式随运行记录保存，历史回看时仍可显示；
- 历史里记录张数、尺寸和字节数，不会重复放大像素；
- 图片只作为该轮输入，不黏到下一轮问题。

## 9.8 会话历史

| 操作 | 说明 |
| --- | --- |
| 查看历史 | 侧栏按本机时区显示“今天 / 昨天 + 时刻” |
| 打开历史会话 | 加载该会话的轮次、工具轨迹与证据 |
| 删除单个会话 | `DELETE /api/reasoning/conversations/:conversationId` |
| 清空历史 | `DELETE /api/reasoning/conversations` |
| 删除后 | 该会话不再出现在列表；审计记录仍保留平台操作记录 |

历史记录存在平台库；智能问答的运行态只在内存里。

## 9.9 回答的可信性

### 工具证据

每次工具调用会从结果中抽取“证据”，例如：

- `OBJECT` / `RELATIONSHIP`：真实对象或关系；
- `OBJECT_TYPE` / `RELATION_TYPE`：对象类型与关系类型；
- `ACTION` / `INTERFACE` / `METRIC` / `GROUP`：定义层概念。

界面上“依据”一行会展示这些证据；有 `instance.read` 权限时，对象证据可以点回对象页核对。

### 回答边界

- 模型只读已发布版本；草稿内容不会作为答案依据；
- 模型只能通过工具访问数据，不能自己编造表名、列名或 JOIN 条件；
- `run_sql` 有行数上限和只读保护，返回被截断时会明确标记；
- 指标是可引用口径，临时聚合会产生“未引用已定义指标”的 warning；
- 证据来自工具结果，不等于业务事实本身；关键结论仍应通过对象页或源表核对。

## 9.10 示例问法

| 问题类型 | 推荐问法 | 期望工具链 |
| --- | --- | --- |
| 概念定位 | “平台里客户相关的对象类型有哪些？” | `search_schema` → `get_object_type` |
| 口径查询 | “互联网专线条数怎么定义的？” | `search_schema` / `list_metrics` |
| 关系探索 | “客户和专线之间通过哪些关系类型相连？” | `search_schema` → `traverse_object_types` |
| 表结构核对 | “列出专线表的字段和状态码值” | `get_object_type` → `get_table_ddl` |
| 数据统计 | “按地市统计未停机专线数量” | `search_schema` → `get_table_ddl` → `run_sql` |
| 对象定位 | “找一下客户张三” | 打开 `query_object_instance` 后：`query_object_instance` |
| 子图分析 | “客户 A 和这条专线怎么连的？” | 打开 `query_instance_subgraph` 后：`query_instance_subgraph` |

## 9.11 权限与审计

| 操作 | 权限 |
| --- | --- |
| 进入智能问答、发起运行、查看自己的运行 | `reasoning.use` |
| 查看会话历史 | `reasoning.use` |
| 修改工具开关 | `mcp.token.manage` |
| 查看审计中的问答记录 | `audit.read` |

每次运行会写 `REASONING_RUN` 审计，包含问题、图片张数、历史轮数、步数、模型、是否截断、是否停止、耗时等；工具开关变更写 `REASONING_TOOL_POLICY_UPDATED`。

## 9.12 当前限制

- 需要外部 OpenAI 兼容模型端点；平台不内置模型。
- 运行态在内存里，进程重启会丢掉正在跑的运行；已落库历史不受影响。
- 问答与 MCP 全部只读；不能通过问答写业务数据。
- `run_query` 尚未开放；当前只读 SQL 走 `run_sql`。
- 对象实例查询与关系子图查询出厂默认关闭，需要管理员显式打开。
- 向量检索没有 embedding 提供方；`search_schema` 当前主要依赖名称、描述、取值画像和关键词。
- 智能问答的配置保存在浏览器本地，不同机器、不同浏览器不共享。
