# 常见任务教程 · 我要做一件事

> 这一页不讲底层原理，只按“我现在想完成什么”给操作步骤。
>
> 第一次使用建议先完成[新手指南](./00-新手指南.md)和[从零跑通第一个本体](./00A-从零跑通第一个本体.md)，再回来按任务查。

## 任务 1：我要登录并确认自己现在在哪个本体

**入口：** 登录页 → 总览

1. 输入管理员提供的邮箱和密码。
2. 登录后进入“总览”。
3. 查看当前本体卡片，确认名称是否正确。
4. 如果当前不是目标本体，在总览里点击要使用的本体。
5. 确认左侧导航是否完整。看不到菜单时，联系管理员检查账号权限。

**完成后：** 页面标题、总览和左侧导航都指向同一个目标本体。

**容易混淆：** 没有权限不等于密码错误。密码错误通常无法登录；权限不足通常能登录，但某个菜单、按钮或数据看不到。

## 任务 2：我要新建一个对象类型，例如“客户”

**入口：** 本体模型 → 本体建模 → 对象类型

**开始前准备：** 先写出对象类型名称、最少五个业务属性、主键字段、显示名称字段。

1. 进入“本体建模”。
2. 点“新建对象类型”。
3. 填写业务人员看得懂的名称，例如“客户”。
4. 填写说明，说明这个对象类型代表什么。
5. 保存。
6. 打开“客户”的编辑弹窗。
7. 添加属性：客户编号、客户名称、状态、所在城市等。
8. 为每个属性填写显示名、类型和说明。
9. 指定主键和展示属性。
10. 保存草稿。

**完成后：** 画布上出现“客户”节点，对象类型清单里能看到属性和主键。

**新手建议：**

- 先只建 3～6 个属性，不要一次搬完整张表。
- 中文显示名和数据库英文列名分开表达。
- 主键不能随便选。它必须能唯一区分一条业务对象。

## 任务 3：我要连接公司的业务数据库

**入口：** 平台 → 数据资源

**开始前准备：** 数据库类型、主机、端口、库/服务名、模式、只读账号和密码。

1. 点“新建数据资源”。
2. 选择类型：PostgreSQL / MySQL / Oracle。
3. 填写连接信息。
4. 点“试连”。
5. 试连成功后保存。
6. 点“刷新结构”或“浏览表 / 视图”。
7. 搜索目标表，例如 `CUSTOMER`。
8. 打开表，确认字段名、类型和几行预览数据。
9. 记住表名和关键字段，后面绑定对象类型时要用。

**完成后：** 能稳定看到目标表和预览数据。

**注意：**

- 平台默认只读访问业务库。
- 试连失败时先检查连接信息和网络，不要反复保存错误配置。
- 没有权限的账号看不到全部表是正常的。

## 任务 4：我要让对象类型读到真实数据

**入口：** 本体建模 → 对象类型 → 编辑 → 数据来源

1. 打开目标对象类型。
2. 选择数据资源。
3. 选择表或视图。
4. 选择主键列。可以多选组成复合主键。
5. 选择展示属性列。
6. 把每个业务属性映射到来源列。
7. 保存草稿。
8. 运行发布校验。
9. 发布新版本。
10. 到对象页选择这个对象类型，确认能看到真实数据。

**完成后：** 对象页列表和详情出现真实对象。

**如果对象页没数据：** 检查来源是否为空、表是否选对、主键是否映射、账号是否有读取权限。

## 任务 4A：我要说明属性码值对应的业务含义

**入口：** 本体建模 → 对象类型 → 编辑 → 配置字典

**开始前准备：** 先在“数据资源”登记字典所在的数据库，确认表或视图、码值列和含义列。例如业务对象的“地市编码”存 `371`，字典表中对应含义是“郑州”。

1. 打开需要解释码值的对象类型，点“编辑”。
2. 找到“配置字典”，添加一张字典表。
3. 选择数据资源、模式和表 / 视图。
4. 填写名称和说明，让使用者知道它解释什么、适用什么范围。
5. 如果已经清楚对应关系，添加映射：选择对象属性，再选择字典的码值列、含义列。例如“地市编码 → AREA_CODE → AREA_CODE_NAME”。
6. 同一张表解释多个属性时，继续添加映射；不同属性来自不同字典表时，继续添加字典表。
7. 暂时不清楚对应关系，可以只登记表、不添加映射；它将作为参考资料，尚不能明确解释某个属性。
8. 保存草稿、校验并发布，让智能问答读取到正式配置。

**完成后：** 对象类型保留字典的位置和可选映射，智能问答可以据此定位码值释义来源。配置本身不会读取整张表，也不会自动把码值变成中文显示。

**容易混淆：**

- 字典用来解释码值，不是补充数据来源；不会改变对象主键、对象数或物化结果。
- 配置字典不需要先建关系类型，也不会自动建关系。需要对象间的遍历时，再单独配置关系类型。
- 同一张共享字典中如果有多种类别、同一码值有不同含义，请先建立只保留目标类别的筛选视图，再登记该视图。
- 查不到含义时，先核对属性、码值列和含义列是否匹配，再确认账号有读取字典表的权限。
- 字典配置不会自动导入属性枚举，也不会自动改变 `LABEL()` 的口径。

## 任务 5：我要建立两个对象类型之间的关系

**入口：** 本体建模 → 关系类型，或在画布上从一个节点拖到另一个节点

**先想清楚：** 要表达的是哪一个现实关系？不要为正反方向各建一条。

### 外键式关系

适用于：一张表里已经有一个字段指向另一张表。

1. 新建关系类型，例如“客户拥有专线”。
2. 起点选“客户”，终点选“专线”。
3. 选择外键式来源。
4. 指定外键长在哪一端，例如专线表里有客户编号。
5. 填写两端键映射。
6. 填写数量关系，例如一个客户可以有多条专线。
7. 保存草稿。
8. 校验并发布。

### 连接表式关系

适用于：两张表通过第三张中间表建立多对多关系。

1. 新建关系类型。
2. 指定起点和终点。
3. 选择连接表式来源。
4. 选择连接表和数据资源。
5. 填写“连接表列 → 起点对象属性”。
6. 填写“连接表列 → 终点对象属性”。
7. 保存、校验、发布。

**完成后：** 对象详情或关系页能看到关系；如果看不到，检查键映射和关系物化状态。

## 任务 6：我要查看对象、搜索对象和看图谱

**入口：** 本体实例 → 对象 / 实例图谱

### 查看对象

1. 进入“对象”。
2. 选择一个对象类型。
3. 默认使用“虚拟查询”，业务数据会按当前版本映射实时投影成对象。
4. 可以在属性筛选栏选择属性、运算符和值；也可以在排序栏选择属性和升降序，再点“应用”。
5. 在搜索框输入名称、编号或属性值查找对象。
6. 点开对象，查看属性、主键和一跳关系。
7. 需要对比时，在“虚拟查询 / 虚拟优先 / 物化索引”之间切换。

**如果筛选或排序报“来自补充来源”：** 当前版本不能跨来源安全下推，给这个对象类型配置一段 `DERIVED` 取数口径，或明确切换到物化索引。

### 查看图谱

1. 进入“实例图谱”。
2. 选择要显示的对象类型。
3. 搜索一个节点并定位。
4. 展开邻居，查看关系。
5. 调整筛选和显示数量，避免一次加载太多节点。

在图谱上方“邻域范围”选择 1、2 或 3 跳，再加载业务对象或展开节点。超过节点/边数上限会提示，不表示所有关系都已加载。

### 编辑后仍能看到源数据更新

1. 在对象页选类型，找到业务对象并取进草稿。
2. 只修改需要修改的属性并保存。
3. 再次读取时，改过字段来自当前版本编辑层，其它字段继续读取当前源数据。
4. 要取消覆盖，在详情里点“恢复源数据”；这不会写业务库。
5. 如果统计被提示存在未写回编辑，先通过动作写回并同步 ODS，或按主键查看该对象，不能把源统计当成合并后的结果。

### 保存与回看历史数据

**入口：** 对象页 → 历史数据。需要先绑定可读取来源和完整主键。

1. 勾选需要保留的类型，点“采集所选类型”。
2. 任务在后台运行；等待完成，可在列表中查看状态和已保存行数。
3. 点“查看”，按冻结定义分页回看采集数据；查看历史不会重读当前业务库。
4. 点“预热”将当前页放入有容量限制的解压缓存。
5. 运行时可取消；完成后可删除快照和压缩页，源业务库不会变化。

**完成后：** 得到一份显式采集的历史数据。它对应采集开始至结束的区间，不承诺跨表事务一致时点，也不能回溯从未采集过的数据时点。

**如果图谱为空：**

- 对象类型和关系类型可能还没物化；
- 关系类型可能没配键映射；
- 两端对象可能不在当前画面；
- 当前版本可能还没发布。

## 任务 7：我要让查询更快，使用对象索引

**入口：** 对象页 → 索引与物化

“物化”可以理解为：把业务库里的对象和关系预先写入可重建的检索副本。默认对象读取不依赖它；当需要全文检索、复杂聚合、跨源宽表或反复查询同一类大数据时，再显式使用它加速。

1. 进入“对象”。
2. 打开“索引与物化”。
3. 查看哪些对象类型和关系类型是可读取的。
4. 选择一个类型或多个类型。
5. 点“物化”或“一键物化全部可读取”。
6. 等待后台任务完成。
7. 查看任务状态、扫描行数、对象数和告警。
8. 物化完成后，回到对象页或实例图谱查看结果。

**注意：**

- 对象物化不等于关系也物化，关系类型要单独处理。
- 两端对象都要物化，图上才能画得出边。
- 主键重复会导致多个源行折叠成一个对象，平台会报出折叠数量。
- 中断、取消或失败后，可以从断点继续。

### 大表先用 ODS，不复制对象实例

如果业务表很大、对象列表反复查询却不需要全文检索，可以只把原始列同步到 ClickHouse ODS：

1. 平台 → 数据资源 → 打开一张表。
2. 点“ODS 镜像”，勾选需要读取的列和复合主键。
3. 第一次选“全量”，后台完成影子表构建后再原子替换。
4. 有可靠更新时间列时可选“增量”，按水位追平新增和更新。
5. 增量同步不会发现源表删除；设置自动全量校准间隔，或定期点“全量校准”。时间过长的任务可以取消。
6. 到对象类型编辑 → 数据来源，把读取路径设为 `AUTO` 或 `ODS`。

切换本体版本不会复制 ODS 数据；对象实例仍然按当前版本的属性映射在查询时形成。
- 清除物化不会删除业务库数据。

## 任务 8：我要修改一个对象，并让它正式生效

**入口：** 本体实例 → 对象

1. 找到目标对象。
2. 点“取进草稿”。
3. 修改属性。
4. 保存。
5. 回到“本体建模”，确认当前草稿包含这次修改。
6. 运行校验。
7. 发布新版本。
8. 重新打开对象页，确认正式版本里能看到修改。

**注意：** 业务库对象不是直接在平台修改后就回写源库。平台当前写的是本体草稿快照。

## 任务 9：我要定义一个业务动作，例如“开通专线”

**入口：** 本体建模 → 动作

1. 先确认“专线”对象类型已经存在，并且有“状态”属性。
2. 新建动作，名称填“开通专线”。
3. 选择作用对象类型：“专线”。
4. 添加参数。如果没有参数，可以先留空。
5. 添加编辑步骤。
6. 选择 `SET_PROPERTY`。
7. 主体选择当前主对象。
8. 属性选择“状态”。
9. 新值填“已开通”。
10. 保存草稿。
11. 进入“运行”阶段，选择一条测试专线。
12. 先做“干跑”，检查会产生什么修改。
13. 确认无误后再正式执行。
14. 查看“决策”记录。
15. 发布新版本，让动作进入正式版本。

**完成后：** 可以在对象上运行“开通专线”，并看到决策记录。

**注意：** 当前动作写入平台草稿快照，不会直接修改生产业务库。

## 任务 10：我要给动作加规则

**入口：** 本体建模 → 规则，或动作编辑页的“规则”阶段

先决定这条规则要做什么：

| 目标 | 选择处置 | 例子 |
| --- | --- | --- |
| 不允许执行 | BLOCK | 已经是“已开通”状态时不能重复开通 |
| 允许执行，但要提醒 | WARN | 客户有欠费，仍允许开通 |
| 条件不满足时干脆不显示动作 | HIDE | 已注销的专线不显示“开通” |

### 配置步骤

1. 新建规则。
2. 选择绑定动作。
3. 填写规则名称和给用户看的提示消息。
4. 选择处置：BLOCK / WARN / HIDE。
5. 添加条件，例如“主对象状态 = 已开通”。
6. 保存草稿。
7. 回到动作的“运行”阶段测试。
8. 用干跑验证规则是否命中。
9. 校验并发布。

**完成后：** 不满足条件时会阻止、提醒或隐藏动作，并在决策记录中留下原因。

## 任务 11：我要用智能问答问业务问题

**入口：** 能力验证 → 智能问答

**开始前确认：**

1. 目标本体已经发布。
2. 管理员已配置 LLM。
3. 你的账号有智能问答权限。
4. 需要用到的查询工具已经打开。

操作：

1. 在提问框输入自然语言问题。
2. 如果需要，先附上图片。
3. 点发送。
4. 查看运行状态和最终答案。
5. 展开“工具轨迹”，看模型查了什么。
6. 展开“依据”，核对对象、关系或指标。
7. 需要停止时点“停止”；切页或刷新不会停止运行。
8. 使用“新对话”开启新话题，不会中断上一轮运行。

好的问法通常包含：

- 对象类型：客户、专线、订单；
- 业务条件：状态正常、欠费、最近一周；
- 想看结果：列表、数量、关系、趋势；
- 时间范围：今天、上月、2026 年第三季度。

**如果回答不准：** 先检查发布版本、字段显示名、对象绑定和工具开关，不要直接怀疑模型。

## 任务 12：我要导入别人给的本体包

**入口：** 总览 → 导入

1. 拿到 `.ontology.json` 本体包或 bkn 知识网络文件。
2. 在总览点“导入”。
3. 上传文件。
4. 查看导入预览和提示。
5. 确认对象类型、关系类型、接口、指标和动作。
6. 保存后系统会创建新本体并停在草稿。
7. 按提示补齐缺失的数据资源绑定。
8. 运行校验。
9. 处理违规项。
10. 发布。

**注意：** 本体包不带实例数据，也不带数据库密码。导入后对象数是 0 是正常现象，需要从本环境数据资源重新读取或物化。

## 任务 13：我要导出一份本体给同事

**入口：** 总览 → 本体卡片 → 导出，或本体建模页头

1. 确认当前发布版本是想要交付的版本。
2. 点击导出。
3. 保存 `.ontology.json` 文件。
4. 把文件交给同事。
5. 同事在目标环境导入。
6. 同事按本环境的数据资源重新绑定和发布。

**导出包含：** 结构定义、关系、接口、指标、动作、规则和数据资源坐标。

**导出不包含：** 实例数据、关系数据、数据库密码、MCP 令牌。

## 任务 14：我要删除草稿或历史版本

**入口：** 本体建模 → 页头右侧“版本记录”

版本删除由“删除版本”权限控制，内置角色默认只有管理员拥有。自定义角色需要在“设置 → 用户与角色”里显式授予。

1. 打开“版本记录”。
2. 找到要删除的草稿或历史归档。
3. 点该行的“删除”。
4. 确认删除。草稿删除后未发布修改会丢失；历史版本删除后不能再激活。
5. 版本列表会自动刷新。

**不能删除：** 当前生效版本。要替换当前版本，先发布新版本，或先激活另一个有实例快照的历史版本。

**删除不会影响：** 图库当前投影、业务库数据和对象索引。

## 任务 15：我要给外部 Agent 或 MCP 客户端使用

**入口：** 能力验证 → MCP 调试

这一项通常由管理员或集成人员操作。

1. 确认本体已经发布。
2. 打开 MCP 调试。
3. 选择平台级或本体级接入地址。
4. 为本客户端单独生成访问令牌，并选好它**代表哪个账号**（默认是你自己；查数据用的是那个账号的权限）。
   如果你的客户端**支持 OAuth**（较新的 Agent / IDE 大多支持），也可以跳过这一步：它连上后会自己注册、
   并把浏览器打开到授权同意页，你登录后点「允许」即可 —— 平台里不用预先配任何东西。
5. 按客户端类型复制配置。
6. 在 MCP 调试页测试工具。
7. 如果某个工具不可用，到工具开关里按全局或按本体打开。
8. 需要审计时在“设置 → 审计记录”查看问答与查询记录。

**注意：**

- 一个客户端一条令牌，不要多人共用。
- 令牌代表一个账号：那个账号被停用或改了角色，令牌立刻跟着失效（这是刻意的，不用等令牌过期）。
- 走 OAuth 接进来的客户端，代表的是**在同意页点「允许」的那个人**；他要能看到的数据，客户端才看得到。
- 已注册的 OAuth 客户端在「MCP 调试 → MCP 接入 → OAuth 客户端」里查看，不认识的直接删（删了会连它的令牌一起作废）。
- 外部 MCP 默认只读。
- 草稿不会作为外部 Agent 的正式读源，先发布版本。

## 任务 16：我要新增用户或调整权限

**入口：** 设置 → 用户与角色

需要用户管理权限。

1. 进入“用户与角色”。
2. 点新建用户。
3. 填写邮箱和初始密码。
4. 选择角色：管理员、编辑者、查看者或自定义角色。
5. 保存。
6. 用户下次请求就会按新角色判断权限。
7. 忘记密码时，在用户行里重置密码。
8. 停用用户后，旧会话会立即失效。
9. 修改角色后，旧令牌也会立即按新权限生效。

**注意：** 平台不会允许删除、停用或降级最后一个能管理用户的账号。
