# 第 14 章 · 运维、安全与故障排查

## 14.1 安全模型

平台的安全边界分四层：

| 层 | 机制 |
| --- | --- |
| 身份 | 登录接口发 8 小时 HS256 JWT；每次请求回库核对用户、角色与权限 |
| 授权 | 13 个模块级权限点；角色 = 权限集合；服务端每个写入/敏感接口执行 `requirePermission` |
| 数据访问 | 业务库只读事务 + 词法 SQL 护栏；图库和平台库只由服务端访问；前端不接触密码和主密钥 |
| 写入边界 | 业务写只能通过动作，且只写草稿快照；原生查询一律只读；发布必须走校验和整图替换 |

关键原则：

- 界面隐藏按钮只是体验，真正的边界在服务端 `requirePermission`；
- 401 与 403 分开：401 是身份不认，403 是权限不够；
- 凭据用 `TARGET_ENCRYPTION_KEY` 加密保存；密钥丢了数据解不开；
- 导入流程不信任外部文件，一律重发 id、停在草稿；
- MCP 和问答只读，且只认已发布版本。

### 浏览器端令牌

- 令牌存 localStorage，前端每个请求附加 `Authorization: Bearer`；
- 换来的是免 CSRF、Postman / curl 直接可调；代价是 XSS 能读走令牌；
- 缓解措施：8 小时过期、服务端每次回库验证、前端不做不可信 HTML 注入；
- 不要在生产环境把令牌打进日志、前端静态文件或公开配置。

## 14.2 数据备份与恢复

### 必须备份

| 数据 | 恢复后的影响 |
| --- | --- |
| `ontology_platform` Schema | 本体定义、版本快照、用户角色、审计、对象索引、列画像 |
| `TARGET_ENCRYPTION_KEY` | 缺它，数据资源凭据和 MCP 令牌都解不开 |
| `AUTH_SECRET` | 缺少它时应用无法签发 / 验证会话；恢复后旧会话失效，重新登录即可。建议与平台库一起保管 |

### 可以重建

| 数据 | 重建方式 |
| --- | --- |
| 图存储投影 | 从已发布版本重新发布，或激活历史版本 |
| 对象索引 | `POST /api/object-search/reindex` |
| 列画像 | 超过 24 小时或显式 `refresh` 时重采 |
| 概念索引 | 保存/发布定义时重建 |
| 技能目录 | 随代码仓库和镜像；源码运行时确保 `skills/` 存在 |

### 恢复步骤

1. 恢复 PostgreSQL 平台库；
2. 恢复 `TARGET_ENCRYPTION_KEY` 与 `AUTH_SECRET`；
3. 启动应用，确认迁移自动执行；
4. 测试图引擎连接；图库丢了就从版本快照重新发布；
5. 测试数据资源连接；凭据解不开就重新登记；
6. 重建对象索引（可选，发布也会同步）；
7. 用对象页、智能问答、审计验证。

## 14.3 监控与巡检

| 检查项 | 方法 | 正常表现 |
| --- | --- | --- |
| 应用健康 | 容器健康检查 / 首页请求 | 2xx |
| 平台库 | 数据库连接、迁移日志 | 无迁移失败、无连接池耗尽 |
| 图引擎 | 设置 → 图引擎配置 → 测试连接 | 返回连接信息与数据集 |
| 数据资源 | 数据资源 → 测试连接 | 返回可用连接 |
| 模型 | `GET /api/reasoning/status` | `configured: true`，模型名正确 |
| 发布 | 审计筛选 `VERSION_PUBLISH_*` | 成功记录；失败记录有原因 |
| 动作 | 审计筛选“动作记录” | 执行与拦截符合预期 |
| MCP | MCP 调试页工具列表 / 试调 | 工具数量与策略一致 |
| 索引 | `GET /api/object-search?targetId=` | `available` 符合预期，条目数正常 |
| 版本 | 本体建模页头 | 当前版本存在，草稿状态清晰 |

### 日志排查顺序

1. 应用日志：启动、迁移、请求错误；
2. 审计记录：谁在什么时候做了什么、失败原因；
3. 图引擎连接测试；
4. 数据资源连接测试；
5. 平台库状态：版本记录、对象索引、列画像；
6. 模型端点：网络、密钥、模型名。

## 14.4 备份与恢复演练

建议定期做一次恢复演练，确认的不只是“备份文件存在”，而是：

- 平台库能恢复到干净实例；
- 密钥能正确解密已有数据资源；
- 用户能登录，角色权限正确；
- 版本记录能读到 `PUBLISHED` 版本；
- 图库能从快照重新发布；
- 对象索引能重建；
- 智能问答能正常起一轮并落库。

## 14.5 常见故障排查

### 14.5.1 登录相关

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 登录后立即回到登录页 | localStorage 被禁用 / 隐私模式 / 令牌没保存 | 换浏览器配置或允许本地存储；检查 `AUTH_SECRET` 是否稳定 |
| 登录成功但刷新后失效 | 换过 `AUTH_SECRET`，或 localStorage 被清 | 重新登录；确认多实例 `AUTH_SECRET` 一致 |
| 返回 401 | 令牌过期、账号被停用或删除 | 重新登录；管理员检查账号状态 |
| 返回 403 | 当前角色没有权限点 | 到设置 → 用户与角色检查角色权限 |
| 改了角色但旧页面还能点 | 界面缓存了旧权限 | 刷新页面；服务端请求会立即按新权限返回 403 |

### 14.5.2 本体与发布相关

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 不能发布 | 发布校验有违规 | 看校验返回的违规清单，逐条修复 |
| 提示存在草稿，不能激活历史版本 | 当前有未发布草稿 | 先发布或删除草稿 |
| 激活历史版本失败 | 该版本没有实例快照，或图替换失败 | 选择有快照的版本；查看 `VERSION_PUBLISH_FAILED` 审计 |
| 发布成功但图里没数据 | 草稿快照本身没有实例，或对象来源没绑定 | 检查对象类型数据来源；从业务库物化或在对象页取进草稿后再发布 |
| 两个本体互相看见数据 | 同一个 Jena 数据集 + 命名图登记了两次 | 改成不同命名图；平台会在新建/编辑时 409 拦下 |
| 清图后版本记录还在吗 | 在 | 清图只动图库，平台版本与快照保留；重新发布会恢复投影 |

### 14.5.3 数据资源相关

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 试连失败 | 主机/端口/账号/网络问题 | 确认平台能访问目标库；检查端口、服务名、账号权限 |
| Oracle 连接报 NJS-138 | 旧服务端不支持 Thin 模式 | 配置 Instant Client，走 Thick 模式 |
| 表清单不更新 | 结构缓存 60 秒内 | 点“刷新结构”，或等缓存过期 |
| 对象类型提示绑定缺失 | `dataSourceId` 为空或指向已删除资源 | 到对象类型编辑里重新选表；导入后用“补齐数据资源绑定” |
| 列画像取值不全 | 列是高基数列（采样种数 > 50） | 这是成本红线；用 `run_sql` 做精确聚合，不要用画像当统计 |
| 列画像日期不对 | 采样只覆盖前 1000 行 | 看返回的 `sample_size` 与采样说明，不要当作全表日期范围 |

### 14.5.4 对象与实例相关

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 对象页看不到数据 | 没有绑定来源 / 没物化 / 没有发布 / 选择的是草稿 | 依次检查绑定、索引、版本与 `origin` 设置 |
| 对象在业务库有、图谱里没有 | 图谱读的是发布投影，业务数据未物化 | 物化索引或重新发布；必要时用 `origin=source` 回源 |
| 取进草稿报“必填属性没有映射来源列” | 属性 required 但没有来源列 | 到对象建模给该属性选列，或取消必填 |
| 动作被 BLOCK | 命中拦截规则 | 看决策记录里的规则名、消息与证据 |
| 动作执行后业务库没变 | 动作只写草稿快照 | 这是设计边界；业务回写尚未实现 |
| 图谱位置刷新后没保留 | 没有草稿或没有编辑权限 | 创建草稿并确认 `instance.write` 权限 |

### 14.5.5 智能问答相关

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 页面提示模型未配置 | `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 缺项 | 补齐三项并重启 |
| SSE 刚连上就 401 | 令牌过期或请求没带 Authorization | 检查前端请求头与令牌有效期 |
| SSE 断连后运行没了 | 进程重启，或运行超过保留时间 | 正在跑的运行存内存，重启会丢；已落库历史不受影响 |
| 提示工具不可用 | 工具被全局或本体策略关闭 | MCP 调试 → 工具，检查“跟随全局 / 本体覆盖” |
| 回答引用对象但点不开 | 缺少 `instance.read` | 补权限；界面会明确提示 |
| 答案被截断 | 工具步数用满、SQL 行数上限、工具结果上限 | 看页脚 `truncated` 与步骤；调整问答配置或分步提问 |
| token 数看起来很大 | 累计 token 是所有模型调用相加 | 区分“上下文 / 输出”与“累计”；后者是计费口径 |
| 同样的答案不稳定 | 模型、提示词、历史上下文、工具策略都可能影响 | 关闭历史（historyTurns=0）复测；检查系统提示词与工具开关 |

### 14.5.6 MCP 相关

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 客户端连上但没有工具 | 工具策略关闭或本体未发布 | 检查工具开关；确认 `PUBLISHED` 版本存在 |
| 平台级端点缺 `ontology_id` | 没先 `list_ontologies` | 先列本体；或改用本体级地址 |
| 401 / 403 | 令牌错误、过期，或账号缺权限 | 重新生成令牌；检查 `reasoning.use` |
| 客户端配置片段地址是 localhost | 反向代理没传 `x-forwarded-*` | 配置代理头，让 `publicOrigin` 拼出正确地址 |
| 令牌清单显示“解不开” | 换过 `TARGET_ENCRYPTION_KEY` | 撤销旧令牌，重新生成 |

### 14.5.7 图引擎与架构相关

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| Jena 连接失败 | 容器 localhost / 端点地址 / 凭据 / 数据集 | 用 `host.docker.internal` 或真实远端地址；检查数据集与账号 |
| 409 提示存储被占用 | 同一数据集 + 命名图登记了两次 | 给本体分配不同命名图或数据集 |
| 发布成功但运行时 Schema 为空 | 图库没有类型、发布的是空定义、或后端读路径异常 | 查看审计与图引擎连接；重新发布验证 |
| 图库数据丢了 | 清图、容器重建、外部存储故障 | 从平台版本快照重新发布 |
| 多实例行为不一致 | 实例配置不同、共享库不对、密钥不一致 | 确保相同的 `DATABASE_URL` / `TARGET_ENCRYPTION_KEY` / `AUTH_SECRET` |

## 14.6 常见操作速查

| 想做什么 | 去哪里 |
| --- | --- |
| 改自己的密码 | 登录后的账号菜单 / `POST /api/auth/password` |
| 新建用户 | 设置 → 用户与角色 |
| 改角色权限 | 设置 → 用户与角色 → 新建/编辑自定义角色 |
| 查谁改了本体 | 设置 → 审计记录，范围“变更记录” |
| 查一次动作为什么被拦 | 动作 → 决策；或审计筛选“动作记录” |
| 查问答访问了哪些数据 | 审计范围“问答与查询” |
| 换图存储 | 设置 → 图引擎配置；迁移后重新发布 |
| 刷新表结构 | 数据资源 → 对应资源 → 刷新结构 |
| 重建对象索引 | 对象检索接口 `POST /api/object-search/reindex` |
| 导出本体结构 | 总览 / 本体建模 → 导出 |
| 批量导入 | `scripts/import-ontology.mjs`，先 `--dry-run` |
| 生成外部 MCP 令牌 | MCP 调试 → MCP 接入 → 访问令牌 |
| 关掉某个模型工具 | MCP 调试 → 工具 → 全局默认或本体覆盖 |

## 14.7 明确边界与后续方向

当前明确未做或未开放的能力：

- `get_property_values`：按列查询取值；用户口径是先不做，取值走列画像。
- `list_tables` / `search_columns`：明确否决；表只能通过对象类型到达。
- 同义词 / 别名层、分区键与表行数、`run_sql` 结果缓存与 dry-run。
- 对象与关系实例层的大规模存储方案；对象索引当前在 PostgreSQL，数据量上来后再选型。
- 查询 DSL：`run_query` 已开放为结构化问数优先入口（关系 JOIN、同一数据资源内的 MDO JOIN 已实现）；跨数据资源 JOIN 仍不支持，真实业务问题集对拍与验收仍在推进。
- 对象实例查询与关系子图工具出厂默认关闭。
- 向量检索缺少 embedding 提供方。
- 动作写回业务库尚未实现。

后续演进方向：

- DSL 多来源与真实问题集对拍；
- 对象索引替换为独立搜索后端（如 OpenSearch / Solr）；
- embedding 提供方接入，启用向量检索；
- 图存储更多后端（NetworkX、Elasticsearch 等）；
- 运行态持久化，让问答跨重启继续；
- 更细的权限点或数据级权限策略。

## 14.8 运维原则

1. **平台库和密钥一起备份。**
2. **图库可丢、可重建；平台库不可丢。**
3. **任何写入口只在草稿，发布才切换已发布视图。**
4. **不要直接改图库**，否则下一次发布会按快照整图替换。
5. **凭据只走加密存储**，不要写进本体包、技能文档或前端配置。
6. **MCP 令牌一条一客户端**，撤销和轮换要可追踪。
7. **排障先看审计**，再看连接测试和日志；审计是平台自己的“事实流水”。
8. **变更先干跑 / 先校验**：动作先干跑，导入先 dry-run，发布先校验。
