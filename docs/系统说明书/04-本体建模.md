# 第 4 章 · 本体建模

## 4.1 本体模型由什么组成

平台把本体模型拆成六类可独立维护、又互相引用的对象：

| 组成 | 作用 | 是否参与发布 |
| --- | --- | --- |
| 概念分组 | 把对象类型按业务域归类，决定画布分组框与检索视图 | 是，随版本发布 |
| 对象类型 | 定义对象有哪些属性、主键、展示属性、接口与数据来源 | 是 |
| 关系类型 | 定义两个对象类型之间的业务关系、连接键、数据来源与数量关系 | 是 |
| 接口 | 定义“实现我的对象类型必须满足什么属性、关系和动作约束” | 是 |
| 动作 | 定义在某个对象类型上的写操作模板 | 是 |
| 规则 | 挂在动作上的拦截、提示、隐藏条件 | 是 |
| 指标 | 把一条业务口径固化下来，供模型和程序引用 | 是 |

> 平台里**没有父子继承**。`entityTypes[].parents`、`class-hierarchy`、父类/子类这类概念已经删除。要表达“多个类型共享同一套形状”，用**接口**。

## 4.2 建模入口与草稿机制

入口：左侧 **本体模型 → 本体建模**。

页面顶部是一排标签，顺序固定：

```text
可视化建模 · 概念分组 N · 对象类型 N · 关系类型 N · 接口 N · 指标 N
```

默认进入“可视化建模”。页头右侧始终显示版本状态：

- 当前发布版本：`当前版本 vN`；
- 存在草稿时并列显示草稿版本；
- 可创建草稿、查看版本记录、激活历史版本。

### 草稿机制

- 第一次编辑会自动创建草稿；草稿优先复制当前发布版本；
- 所有编辑只改草稿，不影响正在被问答和 MCP 读取的已发布版本；
- 画布增删改、属性编辑、关系端点调整、指标编辑都立即写平台库草稿；
- 校验通过后才能发布；发布后草稿状态变为 `PUBLISHED`，旧发布版本变为 `ARCHIVED`；
- 存在草稿时不能激活历史版本，必须先发布或删除草稿。

### 编辑权限

| 操作 | 需要权限 |
| --- | --- |
| 查看模型、版本记录、导出 | `ontology.read` |
| 编辑草稿、绑定数据源、导入 | `ontology.write` |
| 校验、发布、激活、清图 | `ontology.publish` |

## 4.3 可视化建模

可视化建模是默认工作区，适合从整体结构开始搭模型。

### 常用操作

| 操作 | 方法 |
| --- | --- |
| 新建对象类型 | 点“新建对象类型”，或在空白画布上使用工具栏入口 |
| 拉出关系类型 | 从起点对象类型的连接点拖到终点对象类型，会创建一条关系类型草稿 |
| 选中并编辑 | 单击节点或连线，右侧出现详情与“编辑”按钮；编辑对话框就地打开，不跳页 |
| 拖动布局 | 拖动节点改变位置；草稿里的实例位置会写入版本快照，建模画布位置只记在本机浏览器 |
| 切换布局 | 默认 / 圆形 / 按逻辑分组；概念分组框会随节点实时收缩和扩大 |
| 自动整理 | 清掉手工位置，按当前布局重新排列 |
| 搜索 | 按对象类型、属性或关系类型名定位画布节点 |

### 三类连线

画布上会出现三类连线，**每一条都可以点开并回到可编辑的对象**：

| 连线 | 视觉 | 点击后编辑什么 |
| --- | --- | --- |
| 关系类型 | 普通实线，带关系名 | 该关系类型的定义：端点、键映射、来源、数量关系 |
| 实现接口 | 紫色虚线 | 实现关系；选中接口节点或实现方对象类型 |
| 接口承接的关系 | 青绿色实线 | 接口上的关系约束 / 接口承接的关系类型 |

规则：

- 接口节点用紫色虚线圈和 `◇` 标签表示；
- “实现接口”一定是紫色虚线；接口承接的关系不是虚线，用青绿色实线区分；
- 选中实现方对象类型时，它从接口继承来的关系类型会临时挂到实现方身上，让“这个类型实际有哪些关系”一眼可见；
- 不选中任何对象时，接口承接的关系挂在接口节点上，不会重复画成两条平行线；
- 被提取成接口的原对象类型作为影子节点保留，但画布隐藏影子节点，显示紫色接口节点与实现边。

## 4.4 概念分组

概念分组是对象类型的业务域归类，例如“客户域”“产品域”“资源域”。

- 先新建分组，再在对象类型详情或编辑对话框里选择归属；
- 未归组的对象类型显示为“未归组”；
- 分组只影响画布分组布局、颜色框、检索面和工具呈现，**不进图库、不参与推理、不改写对象类型本身**；
- 智能问答可用 `list_concept_groups` 查看分组，按分组找类型；
- bkn 导入会带上概念域分组。

## 4.5 对象类型

对象类型是本体建模的核心。它回答“这一类对象由什么组成、怎么识别、标题怎么显示、数据从哪里来”。

### 4.5.1 基本字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 业务与技术通用名；在界面、工具、本体包里都使用它作为主要引用 |
| 说明 | 否 | 这个类型代表什么、口径边界是什么 |
| 主键 | 发布前建议必填 | 由主来源的表/视图列定义；支持复合主键 |
| 展示属性 | 否 | 对象在列表和图谱上的标题；留空时按属性、主键或 id 回退 |
| 概念分组 | 否 | 所属业务域 |
| 实现的接口 | 否 | 可多选；实现后必须满足接口约束 |
| 属性 | 发布前建议完整 | 对象的字段定义 |
| 数据来源 | 按使用场景 | 主来源 + 可选补充来源；纯建模阶段可以暂时留空 |

### 4.5.2 属性类型

支持以下数据类型：

| 类型 | 说明 |
| --- | --- |
| `TEXT` | 文本 |
| `INTEGER` | 整数 |
| `DECIMAL` | 小数 / 定点数 |
| `BOOLEAN` | 布尔 |
| `DATE` | 日期 |
| `DATETIME` | 日期时间 |
| `TEXT_ARRAY` | 文本数组 |
| `JSON` | JSON 原始结构 |

每个属性还可以配置：

| 配置 | 说明 |
| --- | --- |
| 显示名 | 给人看的名字，例如列名 `STATIS_DATE` 显示为“统计日期” |
| 说明 | 属性口径、单位、业务含义；上限 2000 字 |
| 必填 | 对象缺少该属性时校验失败 |
| 唯一 | 同一对象类型内不允许重复值 |
| 索引 | 为检索/查询提供索引提示 |
| 枚举值 | `码值 → 含义` 映射；模型可用 `enum_label` 操作符按含义过滤 |
| 来源列 | 属性映射到哪一份来源的哪一列 |
| 来源 | 属性来自主来源还是某一份补充来源 |

枚举值是把“只写在列注释里的口径”搬到定义层的关键。比如 `1=全球通`、`2=动感地带`，模型无需再猜码值，`search_schema` 的取值命中也会返回实际可过滤的码值。

### 4.5.3 数据来源绑定

绑定写在对象类型上，而不是逐个对象上，符合 Palantir 的模型：

> 对象类型 ≈ 数据集，对象 ≈ 一行，属性 ≈ 一列。

平台支持**多来源对象类型（column-wise MDO）**：

- `sources[0]` 是主来源，决定对象身份（主键）和标题；
- 后面的来源是补充来源，通过“主表主键列 → 本表对应列”的键映射补齐属性；
- 属性通过 `sourceId` 指回来源，通过 `sourceField` 指向具体列；
- 老快照里的单来源 `source` 字段会自动折成 `sources[0]`，不会丢绑定。

绑定规则分两档：

| 情况 | 处理 |
| --- | --- |
| 补充来源选了表却没有连接键、连接键列数和主键对不上、属性指向已不存在的来源 | **拦发布**，属于自相矛盾的配置 |
| 主来源尚未选表 / 未指定主键、补充来源未选表、同一张表挂两次 | **只提醒**，不拦发布；允许先搭结构后补数据 |

具体操作见第 8 章“数据资源与列画像”。

### 4.5.4 从无数据源对象类型提取为接口

在满足条件时，可以把一个没有数据源的对象类型“提取为接口”：

- 原对象类型与底层关系保留为兼容影子；
- 新增接口记录 `promotedFromEntityTypeId` 指向原对象类型；
- 原对象类型上的关系转成接口的关系约束；
- 画布隐藏影子节点，显示紫色接口节点与实现边；
- **不会**根据关系另一端自动推断谁实现了接口；实现关系必须显式声明。

这样做只是把类型层投影成接口，**不是删除实例数据**。

## 4.6 关系类型

关系类型回答“两个对象类型之间是什么关系、数据上怎么连、走一次会不会放大行数”。

### 4.6.1 关系类型是双向的

一条关系类型只有一个定义、两个端点；建好之后两个方向都能走。

- **不配置正向/反向名字**；
- **不要为正反方向各建一条关系类型**；两条并列关系类型表示的是两个不同的现实关系；
- 界面用 `↔` 表示双向；
- 多跳遍历默认不分方向，可以收窄为 `forward` / `backward`；
- 接口关系约束按双向判定，实现方在这条关系的任一头都算满足。

Palantir 的 link type 也是这个语义；平台与它对齐。

### 4.6.2 端点与键映射

| 配置 | 说明 |
| --- | --- |
| 起点对象类型 / 终点对象类型 | 这条关系连接哪两个对象类型 |
| 起点键映射 | 连接表列 / 外键属性 → 起点对象类型的属性；多行就是复合键 |
| 终点键映射 | 连接表列 / 外键属性 → 终点对象类型的属性；多行就是复合键 |
| 关系属性 | 关系本身也可以有属性，例如生效日期、权重、来源系统 |
| 数据来源 | 关系实例从哪里读：中间表式或外键式 |
| 数量关系 | `ONE_TO_ONE` / `ONE_TO_MANY` / `MANY_TO_ONE` / `MANY_TO_MANY`，空串表示未标注 |

### 4.6.3 两种数据来源

| 模式 | 适用场景 | 配置要点 |
| --- | --- | --- |
| `JOIN_TABLE` | 多对多关系，有一张中间表 | 两端的键映射分别写“中间表列 → 对象类型属性” |
| `FOREIGN_KEY` | 一对一 / 多对一，外键长在某一端对象类型的表上 | 外键那一端填外键属性，另一端填被引用的属性；`view` 留空时用外键所在端的主来源表 |

不配置数据来源不算错：这种关系类型只在类型层声明业务语义，暂时读不出关系实例。发布前校验不会因此拦你。

### 4.6.4 数量关系与聚合安全

数量关系描述的是**起点端 → 终点端**走一次会放大几倍，只用于判断聚合是否会重复计数：

| 数量关系 | 含义 |
| --- | --- |
| `ONE_TO_ONE` | 一个起点最多对应一个终点 |
| `ONE_TO_MANY` | 一个起点可能对应多个终点，按起点聚合会放大 |
| `MANY_TO_ONE` | 多个起点对应一个终点，按起点聚合安全 |
| `MANY_TO_MANY` | 两端都可能多个，聚合默认拒绝 |

它**不是**正反向名字，也不改变关系双向性。反方向查询时平台会自动翻转数量关系来评估。

查询 DSL 的聚合查询遇到可能放大行数的关系会默认拒绝执行，属于 fail-closed：宁可拒查，也不静默算错。

## 4.7 接口

接口（Interface）是平台唯一的抽象机制，语义对齐 Palantir 的 interface。

### 4.7.1 接口能声明什么

| 约束 | 说明 |
| --- | --- |
| 属性 | 实现方必须提供这些属性；可以要求必填、类型等 |
| 关系约束 | 实现方必须有一条符合形状的关系；接口说“应该连什么”，具体关系类型由实现方决定 |
| 动作约束 | 实现方必须有一个动作能完成这件事，并映射到自己的动作 id |
| 接口继承 | 一个接口可以继承多个接口；实现方要同时满足本接口和继承来的约束 |
| 说明 | 接口的用途与适用场景 |

### 4.7.2 对象类型如何实现接口

对象类型在 `implements` 里声明实现哪些接口，并可以配置显式映射：

- 接口属性 `name` 可以映射到实现方自己的属性名，**不要求同名**；
- 没写映射的接口属性按同名匹配；
- 接口动作约束名映射到实现方自己的动作 id，动作必须作用在实现方身上；
- 发布前校验会检查：required 属性是否有映射、关系约束是否满足、动作约束是否映射。

一个对象类型可以实现多个接口，分别服务不同应用场景。

### 4.7.3 画布、工具与右栏三处口径

实现接口 = 继承接口的关系类型，这个语义必须三处一致：

| 位置 | 行为 |
| --- | --- |
| 画布 | 默认接口承接的关系挂在接口节点上；选中实现方时，临时改挂到实现方，让“A 实际有哪些关系”可见 |
| 智能问答工具 | `interfaceDerivedLinks()` 把接口约束算成实现方的边；`get_object_type` 放在 `one_hop.via_interfaces`，`traverse_object_types` 把接口边打上 `via_interface` |
| 关系类型右栏 | 若关系端点落在接口影子上，写明“由接口 X 承接”，并提供“编辑接口”入口，不需跳转到接口标签 |

如果三处只改一处，用户就会看到“接口有关系、实现方却显得孤立”之类的断层。

### 4.7.4 接口编辑

接口按“对象类型那套方式”编辑：

- 右栏只放详情与“编辑”按钮；
- 点“编辑”打开接口对话框，壳与“编辑对象类型”一致；
- 对话框左栏是表单，右栏是画布预览，底部是“取消 / 保存修改”；
- 可改名称、说明、继承的接口、属性、关系约束、动作约束，并勾选谁实现了它（写回对象类型的 `implements`）。

接口标签页保留作为完整视图（继承关系、实现缺口），但不是唯一编辑入口。

## 4.8 指标

指标把业务口径从列注释搬到定义层。一条指标说清“这个数怎么算”，但**不存数、不返回查询结果**。

### 4.8.1 指标字段

| 字段 | 说明 |
| --- | --- |
| 名称 | 指标名，例如“互联网专线条数” |
| 说明 | 口径边界、统计范围、注意事项 |
| 作用对象类型 | 这条指标算的是哪个对象类型 |
| 聚合方式 | `SUM` / `COUNT` / `COUNT_DISTINCT` / `AVG` / `MIN` / `MAX` |
| 被聚合属性 | 聚合作用在哪个属性上；`COUNT` 不填属性表示数行数 |
| 固定过滤 | 口径的一部分，例如“只看互联网专线”“排除红冲” |
| 可用维度 | 可以按哪些属性分组看，例如地市、产品、月份 |
| 时间维度 | 按哪个属性看趋势；留空表示不是时序指标 |
| 单位类型 / 单位 | 原样保留外部定义与业务单位 |
| 状态 | `draft`（未定稿）/ `verified`（已验收） |
| 负责人 / 标签 | 出数有疑问找谁；便于检索和治理 |

### 4.8.2 指标的校验口径

发布前检查由 `metrics.ts` 统一收口：

| 情况 | 处理 |
| --- | --- |
| 指标重名 | 拦发布 |
| 作用对象类型不存在 | 拦发布 |
| 聚合属性、过滤属性、可用维度、时间维度指向不存在的属性 | 拦发布 |
| 没有选作用对象类型 | 提醒，不拦发布 |
| `SUM / AVG / MIN / MAX` 用在非数值属性上 | 提醒，不拦发布 |

### 4.8.3 模型如何看到指标

- `list_metrics`：列出指标定义；
- `get_object_type`：返回该对象类型上的指标；
- 系统提示词的概念清单里会带一行“指标：…”；
- 概念检索 `search_schema` 会检索指标名称、说明和口径。

只加定义、不加这几处，模型看不到指标，就还会去猜口径。

## 4.9 建模体检与发布校验

平台把“建得好不好”和“能不能发布”分成两层。

### 建模体检

建模体检是离线质量规则，只给建议，**不挡发布**：

| 级别 | 含义 | 例子 |
| --- | --- | --- |
| WARN | 该改，影响可用性或一致性 | 空壳对象类型、孤悬类型、主键列没有属性接、命名打架、接口没人实现 |
| INFO | 可以更好，可选优化 | 属性缺少说明、分组策略可以整理 |

它只检查定义内部自洽，不连业务库比对真实列。体检结论带稳定规则码，界面、MCP 工具、技能文档都引用它。

### 发布校验

发布校验管“能不能发布”，拦不住的都算 bug。它会检查：

- 对象类型、关系类型、接口引用的 id 是否存在；
- 关系端点是否合法，端点契约是否满足；
- 必填/唯一属性规则是否自相矛盾；
- 接口实现的属性、关系、动作约束是否满足；
- 补充来源的连接键是否完整、属性是否指向存在的来源；
- 动作定义：作用对象类型、参数、编辑步骤、别名引用是否合法；
- 规则是否绑定了有效动作、条件是否完整、HIDE 是否只依赖主对象；
- 指标的硬性违规；
- 数据源绑定的硬性矛盾。

校验结果分为违规（阻断）和提醒（不阻断）。发布前建议先跑“建模体检”清掉 WARN，再跑发布校验。

## 4.10 建模最佳实践

1. **先定对象，再定关系。** 对象类型是稳定骨架，关系类型是对象之间的连接语义；不要先画一堆连线再回头拆对象。
2. **主键先落。** 没有主键的对象类型可以发布，但对象身份、回源取数、对象索引和关系实例都会受影响。
3. **命名用业务词。** 界面显示名给业务看，机器名给代码和数据列用；两者不要混用。
4. **能写枚举就写枚举。** 码值口径写进定义层，模型和问答应答都会更稳定。
5. **关系类型保持双向语义。** 需要反向名称时优先在应用层表达，不要新建第二条反向关系类型。
6. **抽象用接口。** 不要再引入父子继承；接口属性支持显式映射，不需要强行同名。
7. **指标只写口径。** 不把某个时点的查询结果写进指标描述，也不把固定过滤写成可选项。
8. **先体检再校验再发布。** 体检提升质量，校验负责安全；发布永远走平台流程，不要直接改图库。
9. **绑定来源前先登记数据资源。** 结构缓存和列画像都建立在资源连接和对象类型绑定之上。
10. **改完同步说明书。** 如果改变协议、语义或安全边界，同一交付里更新本章及对应章节。

## 4.11 当前限制

- 没有父子继承，只有接口。
- 关系类型不配置正反向名字；方向由查询时的 `direction` 决定。
- 关系实例目前支持中间表式和外键式两种来源；更复杂的支撑方式暂未覆盖。
- 指标只描述口径，不存数；实际数值仍由查询 DSL / SQL 按对象类型绑定的源表计算。
- 纯建模阶段允许主来源、主键暂时为空，但发布后对象服务可能读不到对象；界面会用提醒而非硬拦截。
- 画布位置是浏览器本地状态；只有草稿实例位置写入版本快照。
- 清单类数据默认给全；只有按分数排序的检索结果才按上限截断，并且必须回传总数与省略数。
