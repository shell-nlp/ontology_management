## 阅读中的状态标记

说明书里会明确区分三种状态，避免把“设计过的”误当成“现在就能用”：

| 标记 | 含义 |
| --- | --- |
| **已实现** | 当前代码与界面已经提供，可按文档操作。 |
| **默认关闭** | 功能存在，但出厂策略关闭；管理员可以在“MCP 调试”里按全局或按本体打开。 |
| **暂未开放 / 规划** | 代码中可能有雏形或预留，但不能当作可用能力；文里会写明原因和触发条件。 |

## 维护规则

1. **功能变，说明书同步变。** 新增模块、修改协议/数据结构、改变语义或安全边界、增加错误码、接入新后端或工具时，必须更新对应章节。
2. **先写“怎么用”，再写“怎么实现”。** 章节先说明用户能看到什么、怎么操作、有什么限制；需要时再补技术实现与代码落点。
3. **状态要如实。** 不把规划写成已实现，不把默认关闭写成完全开放；截断、限制、未覆盖范围都要写清楚。
4. **不写修复流水账。** 历史问题和修复过程放 [历史决策与踩坑](../历史决策与踩坑.md)，这里只保留长期有效的系统结论。
5. **接口以代码和 OpenAPI 为准。** 本文的接口表用于导航；字段、状态码和请求/响应细节以 `/docs`、Zod schema 和路由实现为准。
