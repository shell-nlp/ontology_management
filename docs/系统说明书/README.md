## 第一次使用，按这个顺序看

1. [新手指南 · 先从这里开始](./00-新手指南.md)：知道平台做什么、界面上有什么、名词是什么意思。
2. [跟着做 · 从零跑通第一个本体](./00A-从零跑通第一个本体.md)：按真实操作顺序，从新建本体做到接数据、发布、查对象和问答。
3. [常见任务教程 · 我要做一件事](./00B-常见任务教程.md)：需要完成某个具体任务时，按入口和步骤查。

完成这三篇之后，你已经能完成最常见的操作。下面的章节是“边用边查”的详细说明，不是第一次上手的必读材料。

## 阅读中的状态标记

说明书里会明确区分三种状态，避免把“设计过的”误当成“现在就能用”：

| 标记 | 含义 |
| --- | --- |
| **已实现** | 当前代码与界面已经提供，可按文档操作。 |
| **默认关闭** | 功能存在，但出厂策略关闭；管理员可以在“MCP 调试”里按全局或按本体打开。 |
| **暂未开放 / 规划** | 代码中可能有雏形或预留，但不能当作可用能力；文里会写明原因和触发条件。 |

## 维护规则

1. **功能变，说明书同步变。** 新增模块、修改协议/数据结构、改变语义或安全边界、增加错误码、接入新后端或工具时，必须更新对应章节。
2. **用户教程放前面，技术细节放后面。** 先回答“用户在哪里点、会看到什么、下一步做什么”，再解释实现和接口。
3. **功能教程必须是可执行步骤。** 每个任务要有入口、开始前准备、操作步骤、完成后的结果和常见问题。
4. **状态要如实。** 不把规划写成已实现，不把默认关闭写成完全开放；截断、限制、未覆盖范围都要写清楚。
5. **不写修复流水账。** 历史问题和修复过程放 [历史决策与踩坑](../历史决策与踩坑.md)，这里只保留长期有效的系统结论。
6. **接口以代码和 OpenAPI 为准。** 本文的接口表用于导航；字段、状态码和请求/响应细节以 `/docs`、Zod schema 和路由实现为准。
