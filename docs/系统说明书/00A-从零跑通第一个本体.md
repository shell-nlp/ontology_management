# 跟着做 · 从零跑通第一个本体

> 这是一条完整的入门教程。建议第一次使用时按顺序操作，先做一个很小的例子，不要一上来就搭完整业务模型。
>
> 教程不需要写 SQL，也不需要部署系统；你只需要有平台账号、一个可用的业务库连接信息，以及对应的查看/编辑权限。

## 1. 我们先做一个什么例子

假设公司想在平台里管理“客户”和“服务专线”。

业务事实是：

- 每个客户有一个客户编号和客户名称。
- 每个客户有自己的状态。
- 每个客户可以拥有多条服务专线。
- 每条专线也有自己的编号、名称和状态。

最终想达到的目标：

1. 能查看客户和专线对象。
2. 能看到客户与专线之间的关系。
3. 能搜索某个客户。
4. 能用自然语言问：“目前有哪些正常状态的服务专线？”
5. 以后可以给“开通专线”这样的业务操作定义动作和规则。

> 真实项目的数据通常更复杂。第一次先用一小部分字段跑通，确认流程没问题，再逐步补齐属性、关系和规则。

## 2. 开始前准备这四样东西

| 准备项 | 说明 | 去哪里获取 |
| --- | --- | --- |
| 平台地址和账号 | 能登录系统 | 管理员提供 |
| 账号权限 | 至少能查看本体和对象；要编辑需有编辑草稿权限 | 管理员确认角色 |
| 业务库连接信息 | 类型、主机、端口、库/服务名、模式、用户名、密码 | 数据库管理员或实施人员 |
| 目标表信息 | 客户表、专线表的表名、字段名、主键 | 数据库管理员或数据工程师 |

如果没有编辑权限，可以先做到“查看对象和智能问答”；不要在没有权限的情况下反复点保存。

## 3. 第一步：登录并确认当前本体

入口：打开平台登录页。

操作：

1. 输入管理员给你的邮箱和密码。
2. 登录后进入“总览”。
3. 看一下页面当前打开的是哪个本体。
4. 如果还没有本体，不要急着点其他菜单，先进入下一步。
5. 如果需要切换本体，在总览里选择目标本体卡片。

**做完后你应该看到：** 页面能显示本体列表或当前本体状态，左侧导航可见。

**如果看不到：**

- 看不到菜单：检查账号权限。
- 看不到总览：确认账号没有登录失效。
- 页面提示 403：这是权限不足，不是密码错误。

## 4. 第二步：新建一个本体

入口：**总览 → 新建本体**。

操作：

1. 点“新建本体”。
2. 填写一个业务人员看得懂的名称，例如“客户服务网络”。
3. 填写说明，说明这个本体解决什么业务问题。
4. 第一次建议先使用平台提供的内置图存储。
5. 如果管理员已经配置了外部图引擎，再按管理员的说明选择。
6. 保存后进入这个新本体。

**做完后你应该看到：** 总览里出现“客户服务网络”，当前本体已经切换到它。

**先不要做的事：**

- 不要先建几十个对象类型。
- 不要直接修改图库或数据库。
- 不要跳过草稿机制直接发布。

## 5. 第三步：登记业务数据库连接

入口：**平台 → 数据资源**。

这一步是把平台接到“业务数据真正存放的地方”。平台默认只读访问，不会因为连接了业务库就自动改生产数据。

### 操作步骤

1. 点“新建数据资源”。
2. 选择数据库类型：PostgreSQL、MySQL 或 Oracle。
3. 填写连接信息：
   - 主机；
   - 端口；
   - 数据库或服务名；
   - 模式（如果管理员要求填）；
   - 用户名；
   - 密码。
4. 先点“试连”。
5. 试连成功后保存。
6. 在资源卡片上点“浏览表 / 视图”或“刷新结构”。
7. 找到客户表和专线表。
8. 打开其中一张表，确认能看到字段名和几行预览数据。

**做完后你应该看到：** 数据资源列表里出现新的连接，能看到目标表和字段。

**这一步最重要的判断：** 不是“保存成功”就算完成，必须能看到表、字段和预览数据。

### 常见问题

| 问题 | 先检查什么 |
| --- | --- |
| 试连失败 | 主机、端口、库名、用户名、密码、网络是否可达 |
| 能连上但看不到表 | 模式是否正确，账号是否有该表的读取权限 |
| 表字段和业务人员说的不一样 | 先确认表结构，再到对象类型里做显示名 |
| 不想暴露生产密码 | 使用平台支持的只读账号，不要使用管理员账号 |

## 6. 第四步：创建“客户”对象类型

入口：**本体模型 → 本体建模 → 对象类型**。

对象类型可以先理解成“客户这类东西的定义”。它不等于某一条客户数据，而是告诉平台：客户有哪些信息、用哪个字段区分不同的客户。

### 6.1 先创建基本信息

1. 进入“本体建模”。
2. 在画布上点“新建对象类型”，或进入“对象类型”标签后点新建。
3. 名称填“客户”。
4. 说明填“公司服务的客户”。
5. 保存后，右侧或编辑弹窗里会出现详情与“编辑”按钮。

### 6.2 添加属性

先只添加四个属性，不要一次把所有列都加进来。

| 属性显示名 | 数据类型建议 | 说明 |
| --- | --- | --- |
| 客户编号 | 文本或整数 | 客户唯一身份 |
| 客户名称 | 文本 | 页面展示的标题 |
| 客户状态 | 文本 | 正常、停用等 |
| 所在城市 | 文本 | 业务分析常用 |

操作顺序：

1. 打开“客户”对象类型的编辑。
2. 进入属性区域。
3. 添加“客户编号”。
4. 添加“客户名称”。
5. 添加“客户状态”。
6. 添加“所在城市”。
7. 保存草稿。

> 页面上的中文显示名可以和数据库英文列名不同。例如数据库叫 `CUSTOMER_NAME`，界面显示名可以叫“客户名称”。这样业务人员不需要记表结构。

### 6.3 绑定业务数据

这是让对象真正有数据的关键步骤。

在“客户”对象类型的编辑里找到数据来源：

1. 选择刚才登记的数据资源。
2. 选择客户表或视图。
3. 从表字段中选主键，例如 `CUSTOMER_ID`。如果一条客户由多个列共同决定，就选多列组成复合主键。
4. 选择展示属性，例如客户名称。
5. 把“客户编号”映射到 `CUSTOMER_ID`。
6. 把“客户名称”映射到 `CUSTOMER_NAME`。
7. 把“客户状态”映射到 `STATUS`。
8. 把“所在城市”映射到 `CITY`。
9. 保存草稿。

**做完后你应该看到：** 对象类型详情里能看到来源表、主键、展示属性和属性映射。

### 6.4 如果还没有数据源

也可以先只建对象类型，不绑定数据。这样可以先让业务人员评审定义，但要注意：

- 对象页可能没有数据；
- 智能问答无法从业务库取数；
- 实例图谱不会有真实对象；
- 发布前最好补齐主键和来源。

## 7. 第五步：建立“客户 ↔ 专线”关系类型

入口：**本体建模 → 关系类型**，或在画布上从一个对象类型拖到另一个对象类型。

先重复上一节的做法，创建“专线”对象类型，至少包含：

- 专线编号；
- 专线名称；
- 专线状态。

然后建立关系。

### 7.1 设置关系名称和两端

1. 新建关系类型。
2. 名称填“客户拥有专线”。
3. 起点选“客户”。
4. 终点选“专线”。
5. 页面会用双向关系表示：客户和专线两个方向都可以查看。

### 7.2 选择数据来源方式

最简单的方式是外键式：

- 专线表里有一个客户编号列；
- 这个列指向客户的主键。

那么：

- 客户编号这一端是“被引用方”；
- 专线表里的客户编号是“外键方”；
- 平台可以用专线表的客户编号把专线挂到客户下面。

如果关系数据在第三张中间表里，则选择连接表式，并指定中间表和两端连接列。

### 7.3 填写键映射

1. 起点键映射：填写客户端的业务键。
2. 终点键映射：填写专线端的业务键。
3. 如果需要，填写关系本身的属性，例如生效日期。
4. 选择数量关系，例如一个客户可以有多条专线。
5. 保存草稿。

**注意：** 关系类型是双向的，不要为正反方向各建两条关系类型。两条不同的关系类型应该代表两个不同的业务事实。

## 8. 第六步：做一次建模检查和发布校验

入口：**本体建模页头 → 建模体检 / 校验**。

### 推荐顺序

1. 点“建模体检”。
2. 先看提醒，不需要一次消灭所有提醒。
3. 优先修正会影响业务理解或查询的提醒。
4. 点“校验”。
5. 处理“违规”项，违规会阻止发布。
6. 再点“发布”。

### 第一次最值得检查的五件事

| 检查项 | 为什么要看 |
| --- | --- |
| 对象类型有没有主键 | 没有主键就无法稳定识别对象 |
| 对象类型有没有绑定来源 | 没有来源时对象页没有真实数据 |
| 展示属性是否正确 | 它决定列表和图谱上显示什么标题 |
| 关系两端和键映射是否正确 | 配错时图上看不到边 |
| 必填和唯一规则是否合理 | 规则太严会导致取数或编辑失败 |

发布后：

- 草稿变成当前发布版本；
- 智能问答和外部 MCP 只读取这个正式版本；
- 旧发布版本进入历史记录；
- 平台会重建概念索引并同步发布快照。

## 9. 第七步：查看对象是否真的有数据

入口：**本体实例 → 对象**。

操作：

1. 选择对象类型“客户”。
2. 选择查看口径：
   - “业务库 / 实时取数”用于确认源数据；
   - “已物化对象”用于查看平台索引数据；
   - 不确定时先用默认模式。
3. 在搜索框搜索一个客户名称或客户编号。
4. 点开一条客户，查看属性、主键和关系。
5. 再选择“专线”，确认专线对象也能读出来。
6. 在客户详情里查看一跳关系，确认能看到客户拥有的专线。

**做完后你应该看到：** 对象页能读到真实客户和专线，详情里有属性和关系。

### 如果想看图谱

入口：**本体实例 → 实例图谱**。

如果图谱是空的，通常不是本体被删了，而是：

- 对象和关系还没有物化；
- 当前筛选类型没有数据；
- 两端对象没有同时出现在当前画面；
- 关系类型的键映射还没有配置正确。

到对象页里的“索引与物化”查看对象类型和关系类型的完成状态，必要时按提示逐个物化。

## 10. 第八步：用智能问答问一个业务问题

入口：**能力验证 → 智能问答**。

先确认：

1. 本体已经发布。
2. 账号有智能问答权限。
3. 管理员已经配置 LLM。
4. 需要用到的工具已开启。

可以尝试的问题：

- “客户有哪些主要字段？”
- “状态正常的客户有哪些？”
- “客户和服务专线之间是什么关系？”
- “哪些专线当前不是正常状态？”

提问后不要只看最终答案，还要看：

- **工具轨迹**：模型调用了哪些工具。
- **依据**：答案引用了哪些对象、关系、对象类型或指标。
- **页脚信息**：模型、耗时、上下文、输出和累计 token。
- **警告**：工具结果是否被截断，是否没有引用已定义的指标。

如果回答不对：

1. 先检查本体是否已经发布。
2. 再检查对象类型是否绑定数据源。
3. 再检查字段显示名和业务含义是否准确。
4. 最后再看问答配置和工具开关。

## 11. 第九步：修改一个对象，并让修改正式生效

对象编辑遵循“先取进草稿，再修改，最后发布”的流程。

1. 进入“对象”。
2. 找到目标客户或专线。
3. 点“取进草稿”。
4. 修改需要的属性。
5. 保存。
6. 回到本体建模，查看草稿状态。
7. 运行校验并发布新版本。
8. 重新打开对象页，确认修改已经出现在新版本视图里。

**要记住：** 业务库对象本身不会因为在平台修改就自动回写。平台当前写的是本体草稿快照，正式生效依赖发布流程。

## 12. 第十步：导出一份给同事或别的环境

入口：**总览 → 本体卡片 → 导出**，或“本体建模”页头。

导出得到的是 `.ontology.json` 本体包，里面包含：

- 对象类型；
- 关系类型；
- 接口和指标；
- 动作和规则；
- 数据资源坐标。

不包含：

- 业务库密码；
- 真实对象实例；
- 关系实例；
- 平台内部的版本数据。

同事导入后：

1. 先在草稿里检查对象类型和关系。
2. 按提示补数据资源绑定。
3. 重新校验和发布。
4. 对象数据仍需要从各自环境的数据资源读取或物化。
