# 第 7 章 · 动作与规则

## 7.1 为什么要有动作

平台把“写入业务本体”的权限收口到**动作**这一种入口：

- 智能问答与 MCP 全部只读；
- REST 的对象/关系接口只允许写草稿快照；
- 业务写入不在定义层随意发生，而是通过预定义的动作模板；
- 动作的参数、编辑步骤和规则都在本体定义里，模型或调用方不能自己编造写操作。

动作不是“用自然语言写库”，而是“平台里不存在的动作，就没有对应的写入口”。存在的动作，写法是固定模板。

## 7.2 动作的概念模型

一次动作 = 把声明的操作模板套到当前图上：

```text
选择动作
  → 选择主对象（动作作用的那个对象）
  → 填入参数
  → 在内存中计算执行后的图
  → 用挂在动作上的规则检查结果
  → 全部通过才落盘到草稿快照
```

| 概念 | 说明 |
| --- | --- |
| 动作（Action） | 定义在某个对象类型上的写操作 |
| 主对象（Subject） | 执行时选中的对象，动作作用在它身上 |
| 参数（Param） | 入参，可以是值，也可以是另一个对象的引用 |
| 编辑步骤（Edit） | 按顺序执行的写操作模板 |
| 规则（Rule） | 挂在动作上的 BLOCK / WARN / HIDE 条件 |
| 决策记录（Decision） | 每次干跑、执行、被拦截留一条审计 |

动作类型是本体的一等公民，不是某个对象类型的私有字段；一个动作可以跨多个对象类型写入。

## 7.3 动作定义

入口：**动力模型 → 动作**，或在对象类型详情里跳到相关动作。

动作编辑页有四个阶段：

| 阶段 | 内容 |
| --- | --- |
| 定义 | 动作名称、说明、作用对象类型、参数、编辑步骤 |
| 规则 | 挂在动作上的拦截、提示、隐藏条件 |
| 运行 | 选择主对象、填参数、干跑或正式执行 |
| 决策 | 查看最近的动作执行 / 干跑 / 被拦截记录 |

### 7.3.1 基本字段

| 字段 | 说明 |
| --- | --- |
| 名称 | 动作显示名 |
| 代码 | 稳定标识，供接口和审计使用 |
| 说明 | 这个动作解决什么业务操作 |
| 作用对象类型 | 动作定义在哪个对象类型上；执行时必须选一个属于它的对象 |
| 参数 | 入参定义，见下节 |
| 编辑步骤 | 写操作模板，按顺序执行 |

### 7.3.2 参数

参数有两种：

| 类型 | 说明 |
| --- | --- |
| `VALUE` | 普通值参数，例如金额、状态、日期 |
| `ENTITY_REF` | 对象引用参数，必须指向一个对象类型 |

参数代码（code）在同一个动作内必须唯一。参数失踪、类型不匹配、引用不存在的对象时，动作执行前会被拦下。

### 7.3.3 编辑步骤

平台支持三种编辑操作：

| 操作 | 说明 | 典型用途 |
| --- | --- | --- |
| `CREATE_ENTITY` | 新建一个对象；必须给别名，后续步骤才能引用 | 创建工单、创建任务 |
| `SET_PROPERTY` | 修改某个对象的一个或多个属性 | 更新状态、更新时间 |
| `CREATE_RELATIONSHIP` | 在起点和终点之间新建一条关系 | 把任务挂到客户上 |

对象引用可以来自：

| 引用来源 | 说明 |
| --- | --- |
| `SUBJECT` | 执行时选中的主对象 |
| `PARAM` | 入参中的对象引用 |
| `EDIT` | 前一步创建出来的对象，通过别名引用 |

赋值可以来自常量、参数或前一步创建的对象。编辑步骤按顺序执行，任何一步不符合契约或必填，整次动作都不写库。

### 7.3.4 动作与对象类型 / 关系类型的关联

动作与类型的关联不是单独维护的关联表，而是从参数和编辑步骤推导出来的：

- 入参引用了哪个对象类型 → 标记为“入参”；
- `CREATE_ENTITY` 新建哪个对象类型 → 标记为“新建”；
- `SET_PROPERTY` 修改哪个对象类型 → 标记为“修改”；
- `CREATE_RELATIONSHIP` 创建哪条关系类型 → 标记为这条关系的两端。

这样动作改了，关联就跟着变，不会因为手工维护关联表而漂移。

## 7.4 规则

规则挂在动作上，有三种处置：

| 处置 | 效果 | 适用 |
| --- | --- | --- |
| `BLOCK` | 命中后拒绝执行，把原因与证据返回给用户 | 硬性业务门槛 |
| `WARN` | 命中后照常执行，只提示原因 | 软性提醒、异常但允许 |
| `HIDE` | 命中后这个动作不出现在符合条件的主对象上 | 适用性判断，例如状态不允许时根本不展示 |

### 7.4.1 规则字段

| 字段 | 说明 |
| --- | --- |
| 名称 | 规则显示名 |
| 说明 / 提示消息 | 命中后展示给用户的文字 |
| 处置 | `BLOCK` / `WARN` / `HIDE` |
| 绑定动作 | 规则作用于哪个动作；HIDE 必须绑定具体动作 |
| 优先级 | 多条规则命中时的排序依据 |
| 启用状态 | 可临时停用而不删除 |
| 条件 | 一组条件表达式，支持逻辑组合 |

### 7.4.2 条件主体

条件可以看：

- 主对象（`SUBJECT`）：动作还没执行时就能看到的数据；
- 入参对象（`PARAM`）：调用方传入的对象；
- 前一步创建或修改的对象（`EDIT`）：执行过程中产生的对象；
- 对象属性；
- 关系类型与相关对象。

### 7.4.3 HIDE 的特殊限制

`HIDE` 是“动作在这个对象上出不出现”的问题，必须在动作执行前算得出来，所以：

- HIDE 必须绑定到一个具体动作；
- HIDE 的条件只能看主对象；
- HIDE 条件不能引用入参或执行中新建出来的对象；
- 发布校验会检查这些限制。

这是有意为之：动作还没执行时，入参和新建对象都还不存在，不能拿它们判断动作该不该显示。

## 7.5 干跑与正式执行

### 干跑（Dry Run）

- 完整计算动作结果、执行规则检查；
- 返回会创建的实体、会写入的步骤、命中的拦截/警告/隐藏；
- **不落盘**，不改变草稿快照；
- 适合上线前验证一个动作在当前对象上是否真的能执行。

### 正式执行

- 先检查规则；
- 全部通过后，把执行结果写入草稿快照；
- 被 BLOCK 规则命中时，图保持原样，只留决策记录；
- 执行结果显示创建的实体、主对象、步骤和警告。

### 对象只存在于数据源时

动作作用在草稿快照上；如果主对象或入参对象只存在于业务库，平台会先按主键把它取进草稿，再执行动作。这一步是幂等的，不会重复创建对象。

> 当前动作执行写入的是**平台草稿快照**，不是业务库。业务回写尚未实现，不要把动作当作对生产业务库的写通道。

## 7.6 决策记录与审计

每次动作执行都会落一条审计：

| 审计动作 | 时机 |
| --- | --- |
| `ACTION_DRY_RUN` | 干跑 |
| `ACTION_EXECUTED` | 正式执行成功 |
| `ACTION_BLOCKED` | 被 BLOCK 规则拦截 |

决策记录里包含：

- 动作 id / 代码 / 名称；
- 主对象；
- 干跑与否；
- 判定 `PASSED` / `BLOCKED`；
- 拦截原因、警告、隐藏命中；
- 执行步骤；
- 新建的实体；
- 是否为主对象补了物化。

查看入口：

- 动作页的“决策”阶段显示当前草稿最近的决策；
- 设置 → 审计记录，筛选“动作记录”看完整流水。

## 7.7 权限

| 操作 | 权限 |
| --- | --- |
| 查看动作定义与规则 | `ontology.read` |
| 编辑动作 / 规则草稿 | `ontology.write` |
| 发布动作与规则 | `ontology.publish` |
| 干跑 / 执行动作 | `instance.write` |
| 查看决策记录 | `instance.read` |

## 7.8 一个完整例子

目标：把一条专线标记为“已开通”。

1. **定义对象类型**：`专线`，主键 `线路编号`，属性含 `状态`。
2. **定义动作**：`开通专线`，作用对象类型 = `专线`，参数无。
3. **定义编辑步骤**：`SET_PROPERTY`，主体 = 主对象，属性 `状态` = `已开通`。
4. **定义规则**：
   - BLOCK：主对象 `状态` 已经是 `已开通` 时拒绝，提示“这条专线已经开通”；
   - WARN：主对象 `欠费金额` 大于 0 时提示“存在欠费，仍允许开通”；
   - HIDE：主对象 `是否注销` = 真时隐藏动作。
5. **干跑**：选一条未开通专线，确认步骤和规则命中。
6. **正式执行**：写入草稿快照。
7. **决策记录**：在动作页和审计里看到这一条 `ACTION_EXECUTED`。
8. **发布**：把草稿发布成新版本，动作结果进入新的已发布视图。

## 7.9 当前限制

- 动作只写草稿快照，不回写业务库。
- 动作只能在草稿版本上执行；没有草稿时先创建草稿。
- 没有触发器、定时任务、外部 API 调用等“副作用步骤”；编辑步骤限定在三类图写操作。
- 规则条件只覆盖定义层可见的主对象、参数、编辑对象、属性和关系，不执行任意函数或脚本。
- 动作执行不会绕过必填/唯一/端点契约；任何一步失败，整次动作不落盘。
