# 第 6 章 · 本体实例与对象检索


<!-- BEGINNER-GUIDE-NOTE -->
> 第一次查看对象或图谱，请先看[常见任务教程](./00B-常见任务教程.md)中的“查看对象、搜索对象和看图谱”。本章详细解释索引、物化与回源。

## 6.1 实例层的三个入口

左侧“本体实例”分组有三个页面：

| 页面 | 用途 | 主要操作 |
| --- | --- | --- |
| 实例图谱 | 看对象与关系构成的图 | 按类型筛选、搜索节点、展开邻居、拖动布局、只读查询 |
| 对象 | 按对象类型管理和查看对象 | 列表、属性详情、主键、一跳关系、编辑、跑动作、取进草稿 |
| 关系 | 查看和管理关系实例 | 按关系类型浏览、创建、编辑、删除、跳到端点对象 |

写入操作只作用于**草稿快照**，需要 `instance.write`；只读操作需要 `instance.read`。如果当前没有草稿，编辑动作会先提示或自动建草稿。

## 6.2 对象身份：对象类型 + 主键

对象服务用一层统一口径识别对象：

```text
对象身份 = (对象类型, 主键值)
对象引用 = 对象类型名/主键串
```

主键来自对象类型的主来源 `sources[0].primaryKey`。支持复合主键：

- 主键值统一转成字符串参与比较和哈希；
- 复合主键按 `列=值&列=值` 的形式表达；
- 主键值缺失、超长或为非标量时，该对象不构成稳定身份；
- 对象索引里的唯一键是对象键 `(对象类型, 主键)`，没有主键时退回 `id:<objectId>`，但这不是业务身份。

对象身份的好处是：

- 对象从索引读还是从业务库回源读，身份一致；
- “取进草稿”天然幂等，同一个对象取两次不会造出第二份；
- 动作、问答、MCP 引用对象时都用同一套引用格式。

## 6.3 对象服务：索引优先，缺失回源

对象服务（Object Service）是平台唯一的“按对象类型 + 主键取对象”入口：

```text
界面 / 智能问答 / MCP
        │  (本体, 对象类型, 主键)
        ▼
   对象服务
        ├─ auto（默认）：先查索引，索引里没有就回源
        ├─ index：只读对象索引
        └─ source：只从业务库回源读取
```

三种来源模式：

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| `auto`（默认） | 先查索引；该对象类型在索引里没有数据时回源业务库 | 大多数场景 |
| `index` | 只读对象索引，索引没有就返回空 | 明确要物化数据、要全文/过滤 |
| `source` | 只从业务库按主键回源 | 数据必须实时、不容忍索引延迟 |

对象服务默认使用**已发布版本**的定义；对象页的草稿预览可以点名某个草稿版本。它不认识图库、索引表或业务表的实现细节，换中间件只替换来源实现。

## 6.4 对象索引

对象索引是**派生数据**：任何时刻都可以从已发布快照重建，索引坏了不影响本体版本正确性。

当前实现落在 PostgreSQL `ontology_platform.object_entries`：

| 能力 | 说明 |
| --- | --- |
| 全文检索 | `tsvector`，支持中文分词能力取决于 PostgreSQL 配置 |
| 模糊检索 | `pg_trgm`；缺扩展时降级为全文或属性过滤 |
| 向量检索 | `pgvector` + HNSW；当前还没有 embedding 提供方，向量通道暂不可用 |
| 属性过滤 | `EQ` / `NE` / `CONTAINS` / `GT` / `LT` / `IN` / `EXISTS` |
| 分页 | 检索上限 200 条，偏移最大 100000 |

`GET /api/object-search?targetId=` 会返回能力与统计：

- `available`：索引是否可用；
- `fullText` / `trigram` / `vector`：各通道能力；
- `embeddingDim`：向量维度，未配置时为 null；
- `entries` 与 `byLabel`：索引条目数和按对象类型的分布。

### 物化与增量同步

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 发布 | 发布流程内部调用 | 按发布快照整体同步索引；`prune=true`，以快照为权威 |
| 单条/批量增量同步 | `POST /api/objects/index` | 给主键只同步这几条；不删已有数据 |
| 取进草稿 | `POST /api/objects/materialize` | 把业务库对象取进草稿快照，供编辑或动作使用 |
| 重建索引 | `POST /api/object-search/reindex` | 从版本快照整体替换索引，安全、可重复执行 |
| 对象检索 | `POST /api/object-search` | 全文 + 模糊 + 属性过滤；可带向量 |
| 按主键取对象 | `GET /api/objects` | 走对象服务，可指定 `origin=auto/index/source` |

增量同步只 upsert 不 prune；发布才是权威路径。索引坏了、换后端、扩展缺失，都可以重建，不需要改本体版本。

**来源隔离**：索引行带 `origin` —— `SNAPSHOT`（手工 / 动作 / 取进草稿）与 `MATERIALIZED`（从业务库整份物化）。
发布与「重建索引」只替换 `SNAPSHOT`，不会清掉物化数据；整份物化只动 `MATERIALIZED`。

**默认读法（`entityTypes[].indexPolicy`，2026-10-12）**：`AUTO`（默认，索引有就用、没有回源）/ `INDEXED`（只读索引，
没物化就明确提示、不静默回源）/ `FEDERATED`（不进索引，每次直接读业务库，能力受限并如实标注）。老快照没有这个字段，读出来是 `AUTO`。

**物化按当前打开的版本**（2026-10-12）：面板的可读性与取数都按「有草稿就是草稿」的那一版，汇总栏标出「物化版本 v2 草稿」；
不带版本号会退回已发布版本，于是出现"面板说能读、点下去说读不了"。断点续跑同时带 `kind`（对象类型 / 关系类型）。

**整份物化是后台任务**：一个任务 = 一个**类型**（对象类型或关系类型），服务端串行执行，**默认不限制行数**（读到源读完）；
入队立刻返回任务，进度可在对象页「索引与物化」里看（每页更新一次）。可取消（排队中立刻取消；运行中先标「取消中…」，
等当前这一页读完才转 `CANCELLED`）。失败 / 取消 / 中断只是任务状态展示，不需要清理：在该行直接点「重试物化」或「继续物化」，服务端会从已读断点接着跑
（**断点连游标一起存**，所以哪怕表有几千万行、中间被取消或服务重启过，也能接着翻页继续，不用从头再来一遍）。
任务状态与历史落在 `ontology_platform.materialization_jobs`：进程重启后遗留的 `QUEUED`/`RUNNING` 会被标成 `INTERRUPTED`（物化幂等，重新排队即可）。
半份必须报数：撞到单次上限（调用方显式传 `maxRows`）会停止、不 prune，并写进物化清单 `materialization_manifests`。

**大表怎么物化**（2026-10-14 起）：物化是"**读一页、写一页**"的，内存只跟页大小有关，不跟表的大小有关 ——
所以几千万行的表也能跑，不会把服务撑爆。面板上的「每页」就是每次从业务库读多少行：

- **默认 5000 行**（这也是上限：数据源连接器单次读取的硬上限，填更大也只按 5000 走）；
- 页越大，**往返次数越少、整体越快**（实测 7034 行的表：500 行/页 15 页 16 秒；2000 行/页 4 页 8 秒；5000 行/页 2 页 7.6 秒）；
- 页越大，单次查询在业务库那侧也越重 —— 业务库忙的时候把每页调小（面板上可选 100 / 500 / 2000 / 5000）。
- 中途取消或失败**不会丢数据**：已经写进去的留着，没读到的部分等下次续跑 / 重跑补齐。
  这时索引里是"本次新读的 + 上一次剩下的"混合状态，面板会如实说明。

**主键重复折叠也要报数**（2026-10-13）：整份物化读完之后，用 `countTypeObjects(targetId, 对象类型, MATERIALIZED)`
数一下索引里真正落下几个对象，`scanned - 对象数` 就是**被主键折叠掉的行数**，随清单写进 `materialization_manifests.folded`。
大于 0 时对象页「索引与物化」在该类型那一行挂「主键重复折叠 N 行」，面板底部再给一条红字说明
（哪个类型：源里 X 行 → Y 个对象 → 折叠 Z 行），并写明两条出路：改主键（或换成组合键）、或在取数口径里先去重。
只有「从头读完、没截断、没取消、没卡住」的那一次才算得准；`syncObjectsToIndex` 的「补一批」路径不算（记 0）。
计数走索引的一条 `COUNT`，**不在内存里攒对象键的 Set**（大表会把内存撑爆）。
当前口径是**报数不拦**：物化照常完成，把折叠摊开给用户看，由用户决定改主键还是改口径。

**少读了几行也要说**（2026-10-13）：主键在源数据里不唯一时，主键游标翻页会在**页边界跳过同一主键的其它行**
（`k > 上一页最后一个 k` 永远够不到重复值）。物化读完之后拿源侧报过的总数对账（`total > scanned`），
对不上就报「源里共 N 行，这一趟只读到 M 行…」并给两条出路（改用取数口径 / 换真正唯一的主键）。
**实测**：`GISTOOLS.TB_MK_GRP_LINE_LIST_DAY` 源里 1690 行、物理物化只读到 1688 行 —— 差的 2 行就是这么丢的。

两条配套口径：

- **整份物化自己在翻页，不报"页被截断"**：`ObjectQuery.paging = true` 时不报「命中行数超过 N 行」——
  那是下一页会接着读的常态，报出来只会刷一排假告警（实测一次物化刷 3 条）。
- **后台任务的告警要写进 `job.message`**：`materialize-jobs` 以前只存取消 / 截断 / 失败三种 message，
  物化返回的 `warnings`（折叠多少行、少读几行）整条丢掉。现在完成时把 warnings 并进 message，
  对象页「索引与物化」那一行才看得到。

**对象类型的数据来源有两种形态**（2026-10-13）：

| 形态 | 字段 | 读什么 |
| --- | --- | --- |
| `PHYSICAL`（默认，老快照都是这一档） | `schema` + `view` | 库里现成的表 / 视图 |
| `DERIVED` | `sql`（一段只读 SELECT） | **取数口径**的结果 —— 去重 / 聚合 / 拼装写在 SQL 里 |

- 口径在执行时被**包成子查询**（`SELECT … FROM (<口径>) "t" WHERE …`），过滤 / 排序 / 主键游标翻页全都照旧；
  Oracle 没有 `OFFSET`，用 `ROWNUM <= n + skip` 多读几行、由内存丢掉。
- **只读是硬闸门**：`assertReadOnlySql` 守在两处 —— 发布前（`validateEntitySources`，写语句挡发布）与执行前（连接器里再验一次）。
- 口径必须输出主键列；主键没配只提示、不拦（建模中途允许先搭结构）。
- **补充来源暂不支持口径**，只支持表 / 视图；校验里明确报出来，不静默当表用。
- 语句生成走 `derivedRowsStatement` / `derivedCountStatement`（`src/lib/shared/server/sql-guard.ts`，纯函数、有单测）：
  值一律**绑定参数**、列名一律走驱动转义 —— 口径 SQL 只允许出现在连接器适配器里。
- **界面上在哪配**：「编辑对象类型 → 数据来源」主来源顶部有 `表 / 视图 ↔ 取数口径` 切换（`view-switcher`）。
  切到口径档时给一个 SQL 框 + 主键列（逗号分隔）+ 显示名；SQL 的只读校验**用与后端同一个** `assertReadOnlySql`，
  边写边给结论（通过是绿字，写语句当场报「取数口径只能执行只读查询：…」）。切到口径档会清空表名，避免留下半套绑定。
- **不会写 SQL 就用「按规则生成」**（`src/lib/ontology/dedupe-sql.ts`，纯函数 + 单测）：口径档里选
  「分组键（一个对象一行）+ 取值依据（哪一列）+ 取最新 / 最早」，一次生成**确定的**口径，并把分组键顺手写回对象主键。
  - **候选列只认日期 / 时间**：类型是 DATE / TIME 的，或名字以 `DATE` / `TIME` / `DAY` / `TIMESTAMP` / `_TS` / `_DT` 结尾的
    （很多表的日期是 `VARCHAR2` 存的，只看类型会漏）。**光 `TS` 结尾不算** —— `STATS` 那种状态列会被误判（实测踩过）。
  - **参考表里一个日期列都没有**：不生成 SQL，直接给两条出路 —— 把主键换成真正唯一的键（那就根本不需要去重），
    或按业务条件筛一行（「状态 = 有效」这种，规则由业务定）。
  - **`DERIVED` 来源的 `view` 是「参考表」**：它不参与取数（取数走 `sql`，口径优先），但**要留着** ——
    界面按它拿真实列清单来生成口径。没留参考表时只给指引，**不猜 FROM 子句**。
- **报警之后必须给路**（2026-10-13）：「索引与物化」面板里 `folded > 0` 的那一行下面挂一个「怎么去重？」出口，
  展开给三样东西 —— ① 换主键（并显示当前的去重键是哪几列）；② 这张表能当「取哪一行」依据的**候选列**
  （按参考表的真实列清单挑，与对象类型编辑器**同一个** `orderCandidateColumns`）；③ 按该类型主键**生成好的口径 SQL**
  + 一键复制（**同一个** `dedupeSql`）。一个候选都没有时如实说「这张表没有日期 / 时间列」，把人引回 ①。
  面板只做**只读诊断**：不写任何定义，改动仍回编辑器里做。
- **口径的生成参数（`sources[].rule`）是可选元数据**（2026-10-13）：按规则生成时把
  `{ keyColumns, orderColumn, direction }` 一起存下来。作用有三：
  ① 界面回显**人话**（「按 CUST_ID 取最新一行（依据 STATIS_DATE）」），不用让人读 SQL 才知道口径是什么；
  ② 按规则可以**重新生成**（改一列不用从零选）；
  ③ 平台能判「存下来的 SQL 和这条规则还是不是一回事」—— **对不上时在编辑器里给红字警告**（手改过）。
  手写 SQL 就是 `rule: null`（**逃生舱一直留着**）。发布前只做**结构**校验：有规则但缺分组键 / 缺取值依据 → **挡发布**；
  「SQL 与规则是否一致」要按数据源方言重新生成才知道，所以判断放在编辑器（那里知道 `kind`），不放进定义层校验。

**关系类型的数据来源**（2026-10-12）：形态由**两端键映射**决定 —— 任一端填了「连接列」就是**连接表式**（多对多），
必须给出连接表与数据资源；两端都只填「属性」就是**外键式**（多对一 / 一对一），**可以整块不配**：外键在哪一端按
键映射推断（一侧填该端主键、另一侧填非主键属性），表和数据资源取外键所在端对象类型的**主来源**。
两端键映射都空 = 只在类型层声明，不报错也不出实例。

读不出的关系类型**在这张面板上要看得见**：关系类型那段只列**读得出**的（判据与后端同源 —— 都走 `planLinkSource`，
不另写一套），读不出的（键映射空、或连接表式没选连接表）不进表格，收成表尾一条黄色提示：还有几条读不出、
本份本体共几条、为什么、去哪儿补（到「本体建模」点开关系类型补两端键映射；悬停能看到前几条的具体原因）。
这样"这一段是空的"不会被误读成"这份本体没有关系类型"。
物化的**任务状态并进类型表的那一行**（进行中带进度、失败带原因），不单开任务列表；一个类型只保留最近一条任务记录，
已完成的靠「索引（物化）」那一列表达。表上方的筛选分两行：第一行可读性 + **完成度（全部 / 未完成 / 已完成，各带数量）**，第二行是每页与排队动作；默认「全部」。
每个对象类型行同时显示**当前主键**（未配主键会标黄）；对象类型名称本身可点，直接打开该类型的配置，不用再回到建模页逐项查找。

**关系（边）的物化**（2026-10-12）：关系类型也能整份物化，任务形态与对象侧完全对等（进度 / 取消 / 断点续跑 / 清单）。
一条边存一行：`(关系类型, 起点对象键, 终点对象键)` 是唯一键，**双向共用一个方向不限**（读的时候两个方向都查），
prune 只在这个关系类型里生效。取数走关系类型绑定的 `linkSource`（连接表 + 两侧键映射），整份读连接表。
两端对象类型没物化也能先物化边，但图上要两端都在这一屏里才画得出边，不在就如实报数。

**源侧分页**（2026-10-12；2026-10-14 补漏读兜底）：整份物化按 `pageSize` 逐页回源。**有主键且主键唯一时用主键游标翻页** —— 按主键升序排，
下一页只取"排序键 > 上一页最后一个键"的行（键集翻页），每页等价于点查、offset 恒为 0，不受 Oracle 深翻页上限影响。
第一页也要带排序列（只是不带游标值）；Oracle 上有序取行要先排序再限量（外包一层子查询用 `ROWNUM` 截断）。
主键没配全或断点续跑时退回 `offset` 翻页。回源默认顺带 `COUNT(*)` 报总数，物化只在第一页要它（`ObjectQuery.count = false` 关掉），避免每页一次 `COUNT`。

主键在源数据里不唯一时，严格的主键游标会在页边界跳过重复主键的后续行。整份物化现在会在游标读完后拿源侧总数对账：
一旦发现 `total > scanned`，自动从 0 改用 `offset` 重读；如果 `offset` 也不能读全（例如 Oracle 超过 5000 行的深翻页上限），
任务直接失败，**不会把半份写成"物化完成"**。相邻两页读到的对象若完全相同（分页没前进），也会立即停止并说明，绝不空转。

「索引与物化」面板那一行会同时显示：**当前对象数**（实时从对象索引统计，不拿物化清单的写入条数冒充）、
最近一次物化的**源表行数**、**折叠行数**和是否需要重试的扫描状态。物化清单里的 `rows` 只表示这次提交/写索引的条目数；
历史清单不承担“当前对象数”这个语义。

### 当前限制

- 没有 embedding 提供方；向量列和索引可以建，但生成向量的模型服务尚未接入。
- 索引是最终一致的派生副本；业务库刚更新的数据，索引要等同步或发布才出现。
- 对象索引落在 ClickHouse（列存检索副本）；数据量上来之后，如果要换 OpenSearch/Solr，只需实现对象索引接口。
- Oracle 按 `offset` 浏览有深翻页上限（`ORACLE_MAX_OFFSET = 5000`）；超过上限后普通 `offset` 查询会明确报错，
  不再静默重复同一段数据。主键唯一时整份物化走游标，不受这个上限影响；主键不唯一且 `offset` 兜底也读不全时，物化任务失败并给出改主键 / 改取数口径的出路。
- **实例图谱已发布视图走对象服务**（对象索引 + 边索引）；草稿视图读这一版草稿快照；索引里一条数据都没有时才退回图库并如实说明。
  边要单独物化（见「物化与增量同步」），而且两端对象类型也要物化，点上才画得出边 —— 另一端不在这一屏时界面会报数。
- **对象页「全部标签」也走对象服务**：跨对象类型读索引（回源必须知道是哪张表，全部标签没有单一来源可回）；
  选了具体对象类型才能在「已物化 / 业务库」之间切。
- `pgvector` 缺失时向量检索会明确报错或按能力返回不可用，不会静默降级成假结果。

## 6.5 实例图谱

入口：**本体实例 → 实例图谱**。

### 布局与交互

| 操作 | 说明 |
| --- | --- |
| 按对象类型筛选 | 选择要显示的类型，控制节点数量 |
| 搜索节点 | 按标题或属性搜索，定位后高亮 |
| 展开邻居 | 从节点出发扩展一度邻居，后端无关 |
| 拖动节点 | 拖拽后位置写入当前草稿快照 |
| 布局切换 | 力导向 / 圆形 / 按逻辑分组等（以界面实际提供为准） |
| 节点详情 | 查看属性、主键、对象类型和一跳关系 |
| 只读查询 | 图谱页可展开只读查询；内置图与 Jena 共用同一套模板 |

约束：

- 图谱默认显示数量有上限（常见默认 200 个节点 / 200 条边），可在本机显示设置里调整；
- 位置写回需要 `instance.write`；没有权限时只影响本地视图，不会落库；
- 只读查询写入一律拒绝，避免绕过版本边界；
- 图谱读取的是**对象索引**（已发布视图，物化过什么就画什么）或草稿快照，不能用来当作业务库的实时全量视图；
- 关系（边）**要单独物化**：对象物化了不等于边有了；两端对象类型也物化之后，图上才画得出边。

## 6.6 对象页

入口：**本体实例 → 对象**。

### 能做什么

| 操作 | 说明 |
| --- | --- |
| 按对象类型浏览 | 选择类型后列出对象 |
| 全部标签 | 不选类型时**跨对象类型读对象索引**（回源必须知道是哪张表，全部标签没有单一来源可回） |
| 选择取数口径 | 选了类型才能在“已物化的对象”看索引 / “业务库实时取数”按来源回源之间切 |
| 看属性 | 展示属性、显示名、主键、来源列与值 |
| 看一跳关系 | 关系实例从业务库或已发布图读取；对象可能来自数据源而没有关系，界面会如实说明 |
| 编辑属性 | 先取进草稿，再修改属性 |
| 跑动作 | 对对象执行动作；对象只存在于业务库时先取进草稿 |
| 取进草稿 | 按对象类型 + 主键把业务库对象写入草稿快照，幂等 |
| 查看绑定缺口 | 对象类型还差数据来源绑定时给提示，并提供跳转入口 |

### 取进草稿规则

1. 对象身份是确定性的：同一个对象取两次还是同一条；
2. 取进草稿只写平台库草稿快照，**不写业务库**；
3. 如果必填属性没有映射来源列，取进草稿永远填不上值；平台会直接报错并指向“本体建模”去补映射或取消必填；
4. 有权限限制时，界面会提示先补 `ontology.write` / `instance.write`，而不是给一个空白页。

> 动作引擎作用在草稿快照上，所以“业务库对象”要先取进草稿才能编辑或跑动作。当前平台没有把动作结果回写业务库的能力；动作写的是本体草稿快照。

## 6.8 实例数据的三个来源

看待“对象数据”时，要分清三层：

| 层 | 存什么 | 是否权威 | 读法 |
| --- | --- | --- | --- |
| 业务库 | 真实对象数据与关系数据 | 是，业务系统的事实来源 | 平台通过只读事务回源 |
| 平台版本快照 | 发布版本的实例快照与草稿实例 | 版本的权威副本 | 图库整图替换、对象索引物化的依据 |
| 图存储 | 发布后的投影 | 否，可重建 | 实例图谱、关系遍历、SPARQL/只读查询 |
| 对象索引 | 从快照或业务库派生的检索副本（ClickHouse 列存） | 否，可重建 | 全文、模糊、过滤和分页检索 |


所以出现“业务库里明明有数据，图谱里没有”时，先分清楚是：

1. 对象类型没有绑定数据来源；
2. 数据没有物化进索引；
3. 当前看的是草稿而不是已发布版本；
4. 图存储读的是发布投影，而没有重新发布。

第 14 章有对应的排查路径。

## 6.9 权限与审计

| 操作 | 权限 | 审计动作 |
| --- | --- | --- |
| 查看对象 / 关系 / 图谱 | `instance.read` | 一般只读，不逐个写变更记录 |
| 新建/修改/删除对象 | `instance.write` | `DRAFT_ENTITY_CREATED/UPDATED/DELETED` |
| 新建/修改/删除关系 | `instance.write` | `DRAFT_RELATIONSHIP_CREATED/UPDATED/DELETED` |
| 保存图谱位置 | `instance.write` | `DRAFT_POSITIONS_UPDATED` |
| 取进草稿 | `instance.write` | 随对象创建审计 |
| 同步索引 | `instance.write` | `OBJECT_INDEX_SYNCED` |
| 重建索引 | `instance.write` | `OBJECT_INDEX_REBUILT` |
| 对象检索 | `instance.read` | 不写变更记录 |

## 6.10 当前限制

- 对象服务默认读已发布版本；草稿实例只能在对象页的草稿预览里操作。
- 对象索引不是权威存储，业务库的实时变化不会自动进索引。
- 动作、属性编辑只写草稿快照，不回写业务库。
- 对象/关系实例规模方案尚未最终定型；当前索引在 PostgreSQL，数据量上来后可以替换为独立搜索后端。
- 向量检索缺少 embedding 提供方，暂不可用。
