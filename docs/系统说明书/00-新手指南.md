# 新手指南 · 先从这里开始

> 第一次使用本体管理平台，不需要先懂数据库、编程或图数据库。
>
> 这份指南只回答三个问题：**这个平台能帮你做什么、进入系统后先看哪里、遇到一个任务应该怎么开始。**

## 1. 用一句话理解这个平台

这个平台把公司业务里分散的“客户、订单、设备、线路、区域”等对象整理成一张**业务地图**，让业务人员能看懂、能查询，也让 AI 能按照同一套业务规则回答问题和执行操作。

可以把它想成三步：

1. **先告诉平台业务里有什么**：客户、订单、设备分别是什么，有哪些属性。
2. **再告诉平台这些对象之间怎么关联**：客户属于哪个区域，订单属于哪个客户。
3. **最后把业务数据接进来**：从公司数据库读取真实数据，在对象页、图谱和智能问答中使用。

平台不是单纯的报表工具，也不是一个直接给 AI 开放数据库的聊天框。它先建立一层统一的业务语义，再围绕这层语义提供查询、问答、规则和外部集成能力。

## 2. 先用业务语言认识几个名词

| 你在界面看到的词 | 可以先这样理解 | 例子 |
| --- | --- | --- |
| 本体 | 一套完整的业务世界说明书 | 客户、订单、设备以及它们之间的关系 |
| 对象类型 | 一类东西的定义，类似一张业务表或一个分类 | 客户、订单、专线、设备 |
| 对象 | 这类东西里的一个具体实例 | 客户“张三”、订单“A1001” |
| 属性 | 对象上有哪些信息 | 客户名称、客户编号、状态、所在城市 |
| 主键 | 用来区分“这是哪一个对象”的字段 | 客户编号 |
| 关系类型 | 两类对象之间有什么关系 | 客户 ↔ 专线 |
| 关系 | 两个具体对象之间的一条连接 | 张三 ↔ 专线 A1001 |
| 数据资源 | 平台连接公司业务数据库的配置 | Oracle / PostgreSQL / MySQL 连接 |
| 数据来源绑定 | 某个对象类型从哪张表、哪些列取数据 | 客户对象类型绑定 `CUSTOMER` 表 |
| 草稿 | 正在编辑、还没有正式生效的内容 | 还在修改中的客户对象类型 |
| 版本 / 发布 | 把草稿正式保存成一套可供用户和 AI 使用的版本 | 发布“客户网络 v1” |
| 对象索引 / 物化 | 把业务数据搬到平台的检索副本里，查询通常更快 | 把客户和专线先整份物化 |
| 动作 | 平台允许你在对象上执行的操作模板 | 开通专线、关闭工单 |
| 规则 | 动作执行前的限制、提醒或显示条件 | 已开通的专线不允许重复开通 |

**最重要的理解是：** 对象类型是“定义”，对象是“具体数据”；草稿是“正在改”，发布后才对问答和外部 Agent 正式生效。

## 3. 平台主要能做什么

| 你想要的 | 平台能力 | 常见入口 |
| --- | --- | --- |
| 把业务概念整理清楚 | 新建本体、对象类型、关系类型、接口、指标 | 本体建模 |
| 从公司业务库读取真实数据 | 登记数据库连接、浏览表结构、绑定对象类型 | 数据资源、对象类型编辑 |
| 查看具体客户、订单、设备 | 对象页按类型浏览、搜索、查看属性和关系 | 本体实例 → 对象 |
| 看对象之间连成了什么网络 | 实例图谱、展开邻居、查看节点详情 | 本体实例 → 实例图谱 |
| 用自然语言问业务问题 | 智能问答、工具轨迹、证据和历史会话 | 能力验证 → 智能问答 |
| 修改对象或执行一个业务操作 | 动作、参数、编辑步骤、干跑和执行 | 本体建模 → 动作 |
| 对操作加限制和提醒 | BLOCK / WARN / HIDE 规则 | 本体建模 → 规则 |
| 管理版本、回滚和交付 | 草稿、校验、发布、历史激活、导入导出 | 本体建模、总览 |
| 交给外部 Agent 或系统使用 | MCP 服务、访问令牌、工具开关 | MCP 调试 |
| 管理账号、权限和审计 | 用户、角色、权限点、审计记录 | 设置 |

## 4. 进入平台后，先认识左侧导航

左侧导航按使用目的分成几组。第一次使用不需要把所有页面都点一遍。

| 导航区域 | 你在这里做什么 | 第一次建议 |
| --- | --- | --- |
| 总览 | 查看当前本体、新建或导入本体、看整体状态 | 先确认当前打开的是哪个本体 |
| 本体模型 → 本体建模 | 建对象类型、关系类型、接口、指标、版本 | 第一次从新建一个对象类型开始 |
| 本体模型 → 本体技能 | 下载建模方法技能或查看技能 MCP | 新手可以先不看 |
| 本体实例 → 实例图谱 | 用图的方式查看对象和关系 | 有数据后再看效果最直观 |
| 本体实例 → 对象 | 按对象类型浏览真实对象、搜索、编辑、跑动作 | 最常用的查数入口 |
| 本体实例 → 关系 | 查看、创建、编辑关系 | 对象和关系数据配好后再用 |
| 本体建模 → 动作 | 定义“可以做什么” | 先理解对象类型后再配置 |
| 本体建模 → 规则 | 给动作加限制、提醒和隐藏条件 | 动作能跑通后再配置 |
| 能力验证 → 智能问答 | 用自然语言问业务问题，查看工具证据 | 发布版本后再使用 |
| 能力验证 → MCP 调试 | 查看接入地址、管理工具开关和令牌 | 主要给管理员或集成人员 |
| 平台 → 数据资源 | 登记业务库、浏览表、验证连接 | 有数据库信息时再操作 |
| 平台 → 设置 | 图引擎、用户与角色、审计 | 普通用户通常只使用其中一部分 |

> 看不到某个菜单，通常不是系统坏了，而是当前账号没有对应权限。请联系管理员确认角色。

## 5. 一次完整使用是怎么走通的

```text
登录平台
  → 新建或打开一个本体
  → 建对象类型和关系类型
  → 连接业务数据库并绑定数据
  → 校验、发布
  → 在对象页和实例图谱查看数据
  → 用智能问答提问
  → 需要业务操作时定义动作和规则
  → 修改后发布新版本
```

记住两条最重要的规则：

1. **编辑先进入草稿，正式使用要发布。** 草稿不会影响当前已经发布的版本。
2. **平台查询定义和数据，不等于修改业务库。** 当前动作结果写的是平台草稿快照，不会直接写回生产业务库。

## 7. 新手最容易遇到的 8 个问题

| 现象 | 常见原因 | 先做什么 |
| --- | --- | --- |
| 左侧看不到某个菜单 | 当前账号权限不足 | 找管理员确认角色和权限点 |
| 修改后页面数据没变化 | 还在草稿里，尚未发布 | 完成校验后发布新版本 |
| 对象页没有数据 | 对象类型没有绑定数据资源，或数据库连不上 | 检查对象类型的来源绑定 |
| 实例图谱很空 | 对象和关系还没有物化，或两端对象不在当前视图 | 到对象页的“索引与物化”查看状态 |
| 智能问答说模型未配置 | 管理员还没有配置 LLM | 联系平台管理员 |
| 智能问答只能用一部分能力 | 部分工具出厂默认关闭 | 管理员到 MCP 调试页按需开启 |
| 动作执行后业务库没变化 | 动作写的是平台草稿快照，当前不回写业务库 | 在草稿和发布版本中查看结果 |
| 问“系统有什么功能”也不知道从哪看 | 说明书偏技术参考 | 回到本文的功能表和常见任务教程 |

## 8. 新手可以先不用看的内容

下面这些内容很重要，但**不是第一次使用平台的前提**：

- 环境变量、Docker、部署和数据库迁移。
- REST API、SSE 事件、OpenAPI、查询 DSL。
- Jena/Fuseki 图存储、对象索引适配器、存储中间层。
- MCP 客户端配置、访问令牌、外部 Agent 工具清单。
- 故障排查、备份恢复、内容哈希和底层数据库表。

这些内容仍然在系统说明书里保留，但应放到“需要时查阅”的位置，而不是让第一次使用者从这里开始。

## 9. 你第一次可以使用平台做什么

如果你的账号已经有查看或问答权限，即使还不会建模，也可以先体验：

1. 打开“总览”，看看当前有哪些本体。
2. 进入“对象”，选择一个有数据的对象类型，浏览对象详情。
3. 进入“实例图谱”，查看对象之间的关系。
4. 进入“智能问答”，问一个和已发布本体相关的问题，并展开“工具轨迹”和“依据”。
5. 如果需要自己建模，再继续阅读[从零跑通第一个本体](./00A-从零跑通第一个本体.md)。
