# 第 3 章 · 账号、权限与平台设置

## 3.1 登录与会话

平台使用 **Bearer 令牌**作为登录态，不使用 Cookie：

```http
Authorization: Bearer <平台会话令牌>
```

| 项目 | 行为 |
| --- | --- |
| 登录接口 | `POST /api/auth/login`，请求体是邮箱和密码 |
| 令牌形状 | 无状态 JWT，HS256 签名，密钥来自 `AUTH_SECRET` |
| 有效期 | 8 小时；响应体会返回 `expiresInSeconds` |
| 前端保存 | 浏览器 localStorage；刷新页面仍保持登录，多个标签页共用 |
| 服务端校验 | 每次请求先验签，再按 `sub` 回平台库核对用户、角色和权限 |
| 登出 | `POST /api/auth/logout` 是空操作；前端清掉本地令牌就算登出 |
| 改密码 | `POST /api/auth/password`，需要验证当前密码，不要求用户管理权限 |

因为服务端每次都回库核对用户，所以：

- 停用账号、删除账号、修改角色后，旧令牌会立刻失去对应权限；
- 删除用户不会删除他的历史审计记录；审计中的操作人会变空，并另有一条 `USER_DELETED` 记录邮箱；
- **不要**把令牌写进前端静态配置或用长期有效的方式分发；8 小时过期是刻意的保护。

### 状态码口径

| 状态码 | 含义 | 典型处理 |
| --- | --- | --- |
| `401` | 令牌不认、过期或用户已不存在 | 重新登录 |
| `403` | 登录有效，但当前账号缺少权限点 | 找管理员补权限，或换有权限的账号 |
| `400` | 请求格式或业务参数不合法 | 按错误信息修正 |
| `404` | 资源不存在 | 检查 id、版本或本体是否已删除 |
| `409` | 状态冲突，例如导入后重复初始化、图存储被两个本体占用 | 按提示先处理冲突状态 |

`401` 和 `403` 要分清：**401 是“你是谁不认”，403 是“你是谁认了，但你不能做这个”。**

## 3.2 权限模型

权限点是代码里的稳定常量，界面按模块分组展示。角色是一组权限点，用户绑定一个角色。

### 13 个权限点

| 分组 | 权限点 | 中文名 | 具体能做什么 |
| --- | --- | --- | --- |
| 本体模型 | `ontology.read` | 查看本体与版本 | 查看对象类型、关系类型、接口、指标、版本记录与导出 |
| 本体模型 | `ontology.write` | 编辑草稿 | 新建、导入、编辑、删除本体；编辑草稿中的对象类型、关系类型、接口、指标、动作、规则、分组；绑定数据来源 |
| 本体模型 | `ontology.publish` | 校验与发布 | 校验、发布、激活历史版本；清空与重置图数据 |
| 本体实例 | `instance.read` | 查看对象与关系 | 实例图谱、对象页、关系页、实例检索、引用打开对象 |
| 本体实例 | `instance.write` | 编辑对象与关系 | 增删改对象与关系；取进草稿；图节点位置落库；动作干跑与执行 |
| 数据资源 | `datasource.read` | 查看数据资源 | 资源清单、库表与字段结构、连通性试连 |
| 数据资源 | `datasource.write` | 管理数据资源 | 新建、编辑、启停、删除数据资源；刷新结构缓存 |
| 平台 | `target.read` | 查看图引擎连接 | 图引擎连接清单与连通状态 |
| 平台 | `target.write` | 管理图引擎连接 | 新建、测试、编辑、删除图引擎连接 |
| 能力验证 | `reasoning.use` | 用智能问答与 MCP | 智能问答、对话历史、MCP 只读查询工具 |
| 能力验证 | `mcp.token.manage` | 管理 MCP 访问令牌 | 生成、查看、撤销外部客户端访问令牌；修改工具开关 |
| 平台 | `audit.read` | 查看审计记录 | 查看发布、动作决策与配置变更审计流水 |
| 平台 | `users.manage` | 管理用户与角色 | 建用户、改角色、重置密码、停用、删除；新建和编辑角色 |

> 粒度是**模块级**，不是每个接口一个权限点。这样角色配置人能读懂，服务端也不用维护几百个权限名。

### 内置角色

内置角色不可改、不可删；要定制就复制一份自定义角色。`admin` 角色永远拥有全部权限，即使库存权限被改坏也不会被锁死。

| 内置角色 | 说明 | 拥有的权限 |
| --- | --- | --- |
| 管理员（`admin`） | 平台全权 | 13 个权限点全部 |
| 编辑者（`editor`） | 干活的人：建模、发布、管数据资源与对象 | `ontology.read/write/publish`、`instance.read/write`、`datasource.read/write`、`target.read`、`reasoning.use` |
| 查看者（`viewer`） | 只读：看本体与对象、用问答查询 | `ontology.read`、`instance.read`、`datasource.read`、`target.read`、`reasoning.use` |

编辑者碰不到用户与角色、MCP 访问令牌、图引擎连接；这是“干活的人”和“管平台的人”之间的边界。

### 导航可见性

左侧导航每一项都绑一个权限点；没有权限的功能**不显示**。当前视图没权限时，界面会落到该用户第一个能进的页面，不留下空白页。

| 导航项 | 需要权限 |
| --- | --- |
| 总览 / 本体建模 / 本体技能 / 动作 / 规则 | `ontology.read` |
| 实例图谱 / 对象 / 关系 | `instance.read` |
| 智能问答 / MCP 调试 | `reasoning.use` |
| 数据资源 | `datasource.read` |
| 设置 | 所有登录用户可见；标签页各自判权限 |

设置里的三个标签：

| 标签 | 需要权限 |
| --- | --- |
| 图引擎配置 | `target.read`（新建/测试/编辑/删除需要 `target.write`） |
| 审计记录 | `audit.read` |
| 用户与角色 | `users.manage` |

界面隐藏只是体验；服务端所有相关接口都会独立执行 `requirePermission`。把按钮藏起来不等于安全边界，真正的边界在服务端。

## 3.3 用户与角色管理

入口：**设置 → 用户与角色**。

### 常见操作

| 操作 | 步骤 | 备注 |
| --- | --- | --- |
| 新建账号 | 点新建，填邮箱、初始密码、选角色 | 密码由管理员设置；用户后续可自己改 |
| 改角色 | 在用户行选择新角色并保存 | 改完立即生效；旧令牌下次请求就按新角色判 |
| 重置密码 | 在用户行选择重置密码 | 用于用户忘记密码；重置后旧密码立即失效 |
| 停用账号 | 把用户设为停用 | 停用后旧令牌失效，但审计记录保留 |
| 删除账号 | 删除用户 | 真删；历史审计操作为空，另有 `USER_DELETED` 记录邮箱 |
| 新建自定义角色 | 角色区域点新建，勾选权限点 | 内置角色不能改，但可以复制思路后建自定义角色 |
| 删除角色 | 仅自定义角色可删 | 还有账号在用该角色时不能删 |

### 最后管理员保护

平台不允许把最后一个“能管理用户”的启用账号降级、停用或删除。否则平台会当场锁死，谁也进不来管理界面。

判定依据是该角色是否包含 `users.manage` 权限；如果还想保留至少一个管理员，就不要把唯一的那个账号改走。

## 3.4 图引擎配置

入口：**设置 → 图引擎配置**。

这里管理的是“本体发布后落在哪个图库”，不是业务数据源。

| 操作 | 说明 |
| --- | --- |
| 查看内置图存储 | 平台自带，不需要凭据，不能删除；新建本体时可默认选择 |
| 新建 Jena 连接 | 填 Fuseki 地址、数据集、可选账号密码、命名图等 |
| 测试连接 | 按已保存连接发起一次连通性测试 |
| 查看运行时 Schema | 读取当前图库中已有的类型与统计 |
| 编辑连接 | 修改地址、数据集、凭据等；修改前先确认没有正在发布的任务 |
| 清空图数据 | 需要输入本体存储名称二次确认；只清图库节点与关系，平台版本与快照仍保留 |
| 删除连接 | 删除前确认没有本体还在使用它；图库与平台版本不会一起删除 |

隔离规则：

- 内置图存储按受管目标 id 隔离；
- Jena 的隔离单位是命名图，默认自动分配 `urn:ontology:<本体 id>`；
- 同一个“数据集 + 命名图”不能登记两个本体存储，否则会互相看见并互相清空；平台会以 `409` 拦下。

## 3.5 审计记录

入口：**设置 → 审计记录**。只有 `audit.read` 权限可见。

审计范围有四个：

| 范围 | 包含内容 | 典型用途 |
| --- | --- | --- |
| 变更记录（默认） | 本体、版本、草稿对象/关系、对象索引、图引擎、数据资源的写操作 | 查“谁改了什么” |
| 动作记录 | 动作执行、干跑、被拦截 | 追一次业务写入的决策链 |
| 问答与查询 | 智能问答运行、图查询、模型工具开关变更 | 查模型访问了哪些数据 |
| 全部记录 | 以上全部 | 完整回放 |

审计记录支持按动作、时间、操作人和本体存储过滤，服务端分页。发布、导入、删除、改名、数据资源变更、工具开关、MCP 令牌变更、动作决策都会留痕；失败记录会标红，便于排查。

## 3.6 全局提示与界面反馈

- 成功、失败、权限不足这类全局提示走**底部居中的浮层吐司**（Toast），不会把页面内容往下顶。
- 成功提示约 5 秒自动消失；错误提示等用户点关闭，避免权限说明看不完。
- 登录卡片内部的提示是行内 `Notice`，因为它必须长在表单上下文中。

## 3.7 账号安全建议

- 管理员账号只用于管理，日常建模使用编辑者账号。
- 外部 MCP 客户端**一个客户端一条令牌**，撤销哪条只断哪条，不要多人共用。
- 浏览器端令牌存在 localStorage，XSS 能读走它；前端必须保持严格的内容安全策略，不要把用户内容当 HTML 注入。
- 生产环境使用 HTTPS；反向代理要正确传递 `x-forwarded-proto`，否则公开地址会拼错。
- 定期检查审计里的失败记录，尤其是发布失败、动作被拦截和图引擎连接失败。
- 备份平台库时同时备份密钥；只恢复数据库但丢掉 `TARGET_ENCRYPTION_KEY`，数据资源凭据和 MCP 令牌就解不开。
